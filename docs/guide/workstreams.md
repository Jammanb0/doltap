# 작업 기록

[사용 안내](README.md) · 이전: [표식과 관계](format.md) · 다음: [에이전트와 함께 쓰기](with-agents.md)

새 세션을 열 때마다 "어디까지 했더라"부터 설명하지 않도록, 진행 중인 작업을 짧은 문서로
남깁니다. 사람이 써도 되고 AI에게 맡겨도 됩니다. doltap은 이 문서들이 제자리에 있고 서로
가리키는지만 확인합니다.

## 구조

```text
AGENTS.md                       작업을 시작할 때 .doltap/current.md를 읽으라는 안내
.doltap/
  current.md                    진행 중인 작업 목록
  history.md                    마친 작업 목록
  workstreams/
    002-search-rework/          진행 중인 작업 하나
      README.md                 목적과 범위
      status.md                 현재 상태와 재개 지점
      plan.md                   필요할 때 — 순서와 검증 방법
      decisions.md              필요할 때 — 이후에도 알아야 할 선택과 이유
  archive/
    001-initial-setup/          마친 작업의 기록을 그대로 옮긴 곳
```

`init`은 `AGENTS.md`, `current.md`, `history.md`만 만듭니다. 작업 폴더는 작업을 시작할 때,
`archive/`는 처음 보관할 때, `reviews.json`은 처음 검토를 기록할 때 생깁니다. 필요해지기
전에 빈 폴더나 선택 문서를 미리 만들지 않습니다.

## 언제 작업 폴더를 만드나

여러 단계나 여러 세션에 걸치는 작업, 나중에 이유를 다시 찾아야 할 결정이 있는 작업에
만듭니다. 한 번에 끝나는 수정은 작업 폴더 없이 합니다. 얼마나 엄격하게 가를지는 프로젝트가
정합니다.

폴더 이름은 `<세 자리 번호>-<영문 소문자 이름>`입니다. 번호는 만든 순서이며, 마친 작업의
번호를 다시 쓰지 않습니다. `doltap check`는 진행 중인 작업의 번호가 보관 폴더와 겹치면
알립니다.

작업을 시작하면 폴더에 `README.md`와 `status.md`를 만들고, 두 문서에 문서 범위를 넣은 뒤
`.doltap/current.md`에 링크를 적습니다.

```sh
doltap id .doltap/workstreams/002-search-rework/README.md --apply
doltap id .doltap/workstreams/002-search-rework/status.md --apply
```

```markdown
- [002 검색 개편](workstreams/002-search-rework/README.md) · [상태](workstreams/002-search-rework/status.md)
```

## 문서마다 담는 것

| 문서 | 담는 것 | 담지 않는 것 |
| --- | --- | --- |
| `README.md` | 한 줄 설명, 배경, 범위와 제외 범위, 완료 조건 | 진행 상황 |
| `status.md` | 완료한 것, 진행 중인 것, 확인한 결과, 재개 지점, 막힌 점 | 지나간 단계의 누적 일지 |
| `plan.md` | 단계별 순서, 선행 조건, 단계별 검증 방법 | 진행 체크 |
| `decisions.md` | 이후에도 알아야 할 선택과 그 이유 | 아직 정하지 않은 것 |

`plan.md`와 `decisions.md`는 필요할 때만 만듭니다. 순서를 미리 정해야 하거나 단계마다 검증
방법이 다르면 `plan.md`, 나중에 "왜 이렇게 했지"를 찾게 될 선택이 있으면 `decisions.md`를
둡니다.

## 상태를 남기는 시점

`status.md`는 의미 있는 작업 단위가 끝날 때마다 고칩니다. 작업이 끝날 때 한꺼번에 정리할
기회가 있다고 기대하지 않습니다. 세션이 갑자기 끊겨도 마지막 기록에서 이어받을 수 있어야
합니다.

- 지난 단계를 쌓아 두지 않고 지금 상태로 덮어씁니다.
- 확인한 결과는 무엇을 어떤 조건에서 확인했는지 적습니다. 확인하지 못한 것은 그렇다고
  적습니다.
- 재개 지점에는 다음 세션이 바로 시작할 수 있는 행동을 적습니다.

## 도중에 끊긴 작업을 이어받을 때

마지막 기록 뒤에 파일이 더 바뀌었을 수 있습니다. `status.md`와 실제 변경을 대조한 뒤
이어갑니다. Git을 쓰면 `git status`와 `git diff`로 기록에 없는 변경이 있는지 봅니다.
기록과 실제가 다르면 추측해서 메우지 말고 무엇이 다른지 먼저 정리합니다.

## 마칠 때

1. `status.md`를 마지막 상태로 고칩니다. 결과(완료 또는 취소), 확인한 결과, 남은 일을
   적습니다. 이 파일은 그대로 보관되므로 "진행 중"으로 남기지 않습니다.
2. **앞으로도 적용할 내용이 작업 기록에만 남아 있다면 담당 활성 문서에 반영합니다.**
   규칙은 규칙 문서에, 지원 조건은 지원 안내에 넣는 식입니다. 결정한 이유와 당시 상황은
   작업 기록에 그대로 둡니다. 빠진 것이 있는지는 사람이나 AI가 대조하며, 검사가 이를
   보장하지 않습니다.
3. 보관할 근거가 지금도 성립해야 현재 내용이 유효하다면 현재 문서의 범위에서 그 근거
   범위로 `depends-on`을 선언합니다. 경위만 참고하면 일반 링크로 충분합니다.
   자세한 기준은 [표식과 관계](format.md#보관한-문서와의-관계)에 있습니다.
4. `.doltap/history.md`에 한 줄 적고, `current.md`에서 그 작업의 링크를 뺍니다.
5. 작업 폴더를 통째로 `.doltap/archive/`로 옮깁니다.
6. `doltap check`로 끊어진 링크와 어긋난 관계가 없는지 확인합니다.

```markdown
- 2026-10-05 [002 검색 개편](archive/002-search-rework/README.md) — 완료: 검색 결과를 제목과 본문으로 나눔
```

## doltap이 확인하는 것

| 확인 | 어긋나면 |
| --- | --- |
| `AGENTS.md`가 `.doltap/current.md`를 안내하는지 | 문제 `ENTRY_CURRENT_MISSING` |
| `current.md`·`history.md`와 작업 폴더의 `README.md`·`status.md`가 있고 표식이 있는지 | 문제 |
| 진행 중인 작업 폴더가 모두 `current.md`에 적혀 있는지 | 문제 `WORKSTREAM_UNLISTED` |
| `current.md`가 없는 작업 폴더를 가리키지 않는지 | 문제 `WORKSTREAM_TARGET_MISSING` |
| 보관 폴더가 `history.md`에 적혀 있는지 | 확인 `ARCHIVE_UNLISTED` |

코드별 뜻과 다음 행동은 [검사 항목 참고](checks.md)에 있습니다. 보관 문서의 내용은 당시
기록이므로 링크나 문장을 현재에 맞추라고 요구하지 않습니다.

## 작업 방식은 프로젝트가 정합니다

작업마다 브랜치를 만들지, 언제 커밋하고 누구에게 승인받을지, 계획을 얼마나 자세히 쓸지는
doltap의 규칙이 아닙니다. 엄격하게 운영하고 싶다면 [작업 방식 예시](work-style.md)를
골라 쓸 수 있습니다.
