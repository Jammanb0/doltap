# 검증 기록

doltap은 문서가 어긋난 곳을 찾아 주는 도구입니다. 그런 도구라면 먼저 도구 자신이 안내한
대로 동작해야 믿고 쓸 수 있습니다. 이 폴더에는 doltap 1.0.0을 무엇으로 어떻게 확인했는지
적습니다. 확인한 것만 적고, 어떤 코드를 확인했는지와 다시 확인하는 방법을 함께 남겨 누구든
같은 방법으로 결과를 다시 볼 수 있게 합니다.

## 두 가지 방법으로 확인했습니다

- **시험 프로그램:** `test/` 폴더에 시험 파일 9개, 시험 110개가 있습니다. "이런 문서를 주면
  이런 결과가 나와야 한다"를 하나씩 확인하는 프로그램이고, 시험마다 "코드 블록과 인라인 코드
  안의 표식 예시는 읽지 않는다"처럼 확인하는 동작이 이름으로 적혀 있습니다. `npm test`로 누구나
  다시 돌릴 수 있고, 이 저장소의 첫 커밋에서는 GitHub의 세 운영체제와 Node 두 버전 환경에서도
  모두 통과했습니다([원격 CI](ci.md)).
- **직접 해 본 확인:** 시험과 별도로 실제 사용 흐름을 실행하거나 공식 문서를 대조하고 적은
  보고서입니다. 사용 안내를 처음부터 그대로 따라 해 보고, 실제 배포 묶음을 만들어 풀어 보고,
  안내의 설명을 다른 회사의 공식 문서와 한 줄씩 대조했습니다.

## 어떤 코드를 확인했는지

직접 해 본 보고서에는 확인한 코드를 가리키는 **구현 해시**를 적습니다. 실행 코드(`bin/`,
`lib/`)와 `init`이 만드는 기본 구조(`template/`)의 내용으로 계산한 값이라, 이 파일들이 한 글자만
바뀌어도 달라지고 문서만 고쳤을 때는 그대로입니다. 지금 저장소의 값은
`node scripts/implementation-hash.mjs`로 볼 수 있고, 보고서에 적힌 값과 같으면 같은 코드를 확인한
결과입니다.

시작하기 흐름, 배포 파일, 원격 CI 보고서는 모두 구현 해시 `3b36e425…`를 대상으로 했습니다.
에이전트 지시 파일 보고서는 코드가 아니라 사용 안내의 설명을 공식 문서와 대조한 것입니다.

## 다시 확인하는 방법

소스 폴더에서 아래 명령으로 시험과 두 검사를 다시 돌릴 수 있습니다. 직접 해 본 확인은 각
보고서의 「재실행」을 따릅니다.

```sh
npm test
node bin/doltap.mjs check template
node bin/doltap.mjs check .
```

시험 통과는 시험이 고른 입력에서 기대한 결과가 나왔다는 뜻입니다.
