## 실패 내용

Windows / Node 24.20.0에서 ids.test.mjs의 「두 프로세스가 동시에 발급해도
같은 ID 가 두 줄이 되지 않는다」가 실패했다. 두 자식 프로세스가 각각 25개를
발급하는 시험이다. ids.lock을 wx 모드로 여는 tryCreateLock에서 EPERM이
발생해 자식 프로세스가 종료됐다. 이 실행은 199개 통과, 1개 실패다.

로그에서 확인된 것은 실패 지점과 오류 코드다. 운영체제 내부에서 왜 EPERM이
발생했는지, 이전에 상세 로그 없이 보고된 실패와 같은 원인인지는 확정하지 않았다.
로컬에서 통과했던 시험을 원격까지 통과했다고 확대하면 안 되는 사례다.

## 로컬 보완과 해석 범위

010 로컬 브랜치에서 Windows의 잠금 생성 open에 한해 EPERM이면 최대 40회까지
시도하고, 실패 사이 10ms 간격을 두도록 보완했다. 다른 주인의 잠금을 지우지 않고
매번 wx 배타적 생성으로 소유권을 얻는다. 오류가 지속되면 원래 오류를 전달한다.
파일 생성 뒤 내용 쓰기·닫기 오류에는 이 재시도를 적용하지 않는다.

오류 주입으로 재시도 후 성공, 다른 주인의 EEXIST 발견, 지속 오류, Windows 밖
오류를 확인한다. 시험 결과는 [ID 발급 보고서](automated/ids.md)에 있다.
로컬 Windows / Node 22.14.0에서는 동시 발급 시험을 추가로 20회 실행해 통과했다.
이는 해당 오류 처리 경로의 회귀 검증이다. 이 보완은 push하지 않았으므로
Windows / Node 24 원격 재실행 성공을 주장하지 않는다.
