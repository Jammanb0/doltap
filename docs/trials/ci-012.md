# 012 CI 시험 안정화 검증

[시험 보고서 목록](README.md) · [ID 시험 원본](../../test/ids.test.mjs) · [파일별 실행 보고서](automated/ids.md)

## 원격 실패 근거

- v0.4.1 / 4bb5009의 [실행 34817927152](https://github.com/Jammanb0/doltap/actions/runs/34817927152):
  Ubuntu / Node 22는 208개 중 207개 통과, 1개 실패. 다른 다섯 환경은 통과.
- [실패 job 103892593987](https://github.com/Jammanb0/doltap/actions/runs/34817927152/job/103892593987)의
  npm test 단계에서 `읽지 못한 잠금을 오래된 것으로 보지 않는다`가 실패했다.
  수정 전 test/ids.test.mjs:244의 기대값은 true, 실제값은 false였다.
- 010 종료 커밋의 [실행 34764974816](https://github.com/Jammanb0/doltap/actions/runs/34764974816)에서도
  같은 시험과 단언이 실패했다. 실패 당시 프로세스 목록은 로그에 없으므로
  PID 1234가 어떤 프로세스였는지는 확인하지 못했다.

## 원인과 수정

시험이 PID 1234의 주인이 없다고 가정한 채 기본 OS 조회를 사용했다.
`isStaleLock`은 시각이 오래됐어도 주인이 살아 있으면 false를 반환한다.
프로세스 조회가 성공하거나 EPERM을 반환하는 환경에서는 시험의 기대값이 틀린다.

잠금 형식 시험에는 주인이 없다는 판정을 주입했다. 동시에 process.kill이
살아 있다고 응답하게 하고 호출 횟수가 0인지 검사하여 OS 조회가 다시 섞이면
반드시 실패하도록 했다. 죽은 잠금 회수 시험의 PID 999999 가정과 프로세스 조회
시험의 큰 PID 가정도 없애고, 테스트별 mock으로 ESRCH·EPERM·성공을 구분한다.
mock은 Node 기본 시험 러너의 테스트 컨텍스트가 종료 시 복원한다.

제품 구현과 CI 행렬은 변경하지 않았다. 실제 자기 PID의 생존 확인과 두 자식
프로세스가 함께 50개 ID를 발급하는 시험도 유지했다.

## 로컬 실행

환경: Windows x64 / Node v22.14.0. 대상은 main 4bb5009에서 분기한
codex/012-ci-stability의 미커밋 작업 트리다. 정확한 시험 파일 해시는 파일별
실행 보고서에 있다.

- 수정 전: Node의 --import preload로 PID 1234에 대한 process.kill(pid, 0)이
  성공하도록 주입하고 해당 시험만 실행했다. 1개 실패, 종료 코드 1,
  `false !== true`를 재현했다.
- 수정 후: 같은 preload와 시험 이름 필터로 20회 실행했다. 20회 모두 1개 통과,
  종료 코드 0이었다. 이는 잠금 시험의 환경 가정 검증이며 Linux 실행은 아니다.
- `npm test`: 208개 통과, 실패·건너뜀 0개.
- `node scripts/report-tests.mjs --check`: 보고서 8개와 208개 시험 일치.
- `node bin/doltap.mjs check .`: 문제·확인 0개.
- `node bin/doltap.mjs check template`: 문제 0개, 채우기 안내 5개.
- `git diff --check`: 통과.

재실행할 핵심 회귀 시험은 다음 명령으로 확인할 수 있다. 살아 있는 PID 응답은
시험 자체에도 고정해 두었으므로 별도 preload 없이 같은 오류의 재발을 잡는다.

```sh
node --test --test-name-pattern="읽지 못한 잠금을 오래된 것으로 보지 않는다" test/ids.test.mjs
node --test test/ids.test.mjs
```

## 해석 범위

위 로컬 검증 시점에는 사용자 요청으로 커밋·푸시·대작업 종료를 하지 않았다.
로컬 Linux 환경도 설치돼 있지 않아 Ubuntu / Node 22의 실행 결과를 대신
주장할 수 없다. 후속 승인으로 main 반영·푸시한 결과는 아래 원격 실행으로
확인했다. 과거 실패 실행의 결과는 소급해서 바뀌지 않는다.

## 수정 후 원격 CI

main의 37249cf에서 [실행 34865717622](https://github.com/Jammanb0/doltap/actions/runs/34865717622)를
확인했다. Ubuntu·macOS·Windows × Node 22·24의 여섯 job이 모두 성공했으며,
각 job의 npm test, check template, check . 단계가 통과했다.

이 결과는 해당 커밋과 실행의 검증이다. 모든 미래 환경의 파일 잠금 동작을
보장하지 않는다. 제품 배포 파일은 v0.4.1과 같으며 새 릴리즈는 만들지 않는다.
