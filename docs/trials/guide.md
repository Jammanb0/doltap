[시험 보고서 목록](README.md) · [시나리오 원본](../../scripts/verify-guide.mjs)

## 방법

- 실행일: 2026-09-13
- 환경: Windows x64, Node 22.14.0
- 실행: `node scripts/verify-guide.mjs`
- 대상: 010 작업 브랜치의 CLI와 안내 문서
- 준비: Git을 초기화하지 않은 새 임시 폴더에 CLI로 골격 생성
- 판정: 각 CLI 종료 코드 0과 JSON 결과·파일 상태를 대조하는 assert

가이드의 자리표시자 ID는 실제 발급한 값으로 바꾸어 실행한다.
기존 사용자 프로젝트나 이 저장소의 작업 문서를 시험 대상으로 지우지 않는다.

## 결과

CLI 호출 38개가 통과했다. 시나리오별로 확인한 것은 다음과 같다.

| 시나리오 | 판정 |
| --- | --- |
| init → check | 문서 골격 생성과 검사 통과 |
| ID 미리보기 → 적용 → 관계 추가 | 미리보기는 쓰지 않고 실제 ID로 문서와 절 연결 |
| map → context → audit | 실제 ID·관계로 JSON 조회 |
| 노드·관계 검토와 감사 제안 기록 | 이유·주체를 받아 정상 기록 |
| 파일 이동 → move-fix | 기존 ID 유지와 경로 수정 후 검사 통과 |
| 절 삭제, 파일 직접 삭제 → delete-fix | 살아 있는 절과 사라진 문서의 절차를 구분해 처리 |
| 폴더 묶음 삭제 → recover → discard | 문서와 부모 복원 후 해당 복구 자료 폐기 |
| 대작업 생성 → current → 완료 기록 → archive → history | 폴더 이동·관계 갱신 뒤 검사 통과 |

같은 스크립트로 README 두 벌·APPLY·가이드 11개에서 코드 예시를 제외한
로컬 링크 목적지 파일 73곳이 존재하는지 확인했다. 외부 URL·모든 Markdown
확장 문법·렌더러의 조각 이동을 이 숫자에 포함하지 않는다.

## 읽는 순서·기본 승인 규칙 보완 뒤 재검증

같은 날 guide/README를 입문 4개와 상황별 참고 6개로 나누고, 입문 문서 끝의
이동 안내와 workstreams의 기본 승인·사용자 설정 설명을 보완했다. 파일명과
CLI 동작은 바꾸지 않았다. 승인 설명은 template/AGENTS.md와
template/.doltap/plans/workstreams.md의 현재 기본값에 대조했다.

`node scripts/verify-guide.mjs`를 다시 실행해 CLI 호출 38개와 로컬 링크 목적지
파일 75곳을 확인했다. 앞의 73곳은 보완 전 실행 결과다. check·workflow 시험
86개도 통과했고, 저장소 check는 문제·확인 0개, template check는 문제 0개와
미완성 자리 안내 5개였다. 새 순서의 사용자 이해도나 Markdown 렌더러 화면은
이번 검증에 포함하지 않았다.

## 배포와 설치 주소

이 절의 실제 tarball·npx 실행은 초기 가이드 작성 시점의 결과다. 아래 후속 보완의
배포 확인은 `npm pack --dry-run`이며 실제 tarball 실행과 구분한다.

실제 `npm pack`으로 만든 tarball을 임시 폴더에 풀고 그 안의 CLI로 init → check를
실행해 통과했다. 패키지 파일 44개 중 guide의 Markdown 11개가 들어 있으며
옛 GRAPH.md는 없다. 복구·시험·개발 문서는 배포 대상이 아니다.

`npx --yes github:Jammanb0/doltap check template`도 실제 실행해 통과했다.
이 명령은 원격 main의 패키지를 받는 설치 경로 검증이다. 로컬 가이드와 잠금 수정이
원격에 반영됐다는 근거로 사용하지 않는다.

## 환경별 적용 절차 보완 뒤 재검증

같은 날 APPLY의 조사 범위를 운영 루트·코드 저장소·골격·에이전트 시작 위치로
구분하고, 적용·해당 없음·미확인 결과를 세팅 계획과 활성 운영 규칙에 연결했다.
guide/adoption-layouts.md를 추가하고 세팅 문서·배포 골격·README 두 벌을 맞췄다.
APPLY는 315줄에서 229줄로 줄었고 구성 사례와 골격 위치 설명은 별도 안내에 뒀다.

- 전체 시험 202개 통과. CLI 구현과 시험 사례 자체는 바꾸지 않았다.
- `node scripts/verify-guide.mjs`: 기존 CLI 시나리오 38개와 로컬 링크 목적지 파일
  85곳 통과. 새 안내 파일도 이후 링크 검사 대상에 추가했다. init → check를 포함한다.
- `check .`: 문제·확인 0개. `check template`: 문제 0개, 미완성 자리 안내 5개.
- `npm pack --dry-run --json`: 배포 예정 파일 45개, guide 12개와 새 구성 안내 포함.
  기본 npm 캐시에 쓸 권한이 없어 임시 캐시를 지정해 확인했다. 이번에는 실제
  tarball·원격 설치·원격 CI를 다시 실행하지 않았다.

사용자 요청에 따라 전달받은 부모·회사 레포 실험은 재현하지 않았다. 이 절의 시험은
기존 CLI와 기본 골격의 회귀 확인이며, 문서에 나온 특수 구성의 새 실행 증거가 아니다.
Git 제외와 에이전트 지침·접근·설정의 차이는 구성 안내에 연결한 공식 문서 및 현재
코드와 대조했다. 새 세션의 지침 준수와 Markdown 화면은 이번에 검증하지 않았다.

## 해석 범위

시나리오는 정상 사용 흐름의 실행 검증이며 사용자가 글만 읽고 이해하는지 관찰한
사용성 시험은 아니다. 오류 입력과 복구 실패는 파일별 자동 시험에서 별도로 다룬다.
실제 Git 반영·push·에이전트 승인 준수와 사용자 설정에 설치한 훅 실행도 이 시험의
대상이 아니다. 009 원격 CI와 로컬 보완의 차이는 [별도 보고서](ci-009.md)에 있다.
