# 문서 그래프 현재 사양

구현을 고칠 때 따르는 현재 형식입니다. 배경은 [설계](document-graph-design.md),
명령 사용법은 [사용 안내](../guide/reference.md), 실행 근거는 [시험 보고서](trials/README.md)에
있습니다. 워크스트림의 조사 과정은 현재 사양의 원본이 아닙니다.

## ID와 앵커

공개 이름·명령·패키지는 doltap, 운영 폴더는 .doltap, 임시 클론은
.doltap-bootstrap입니다. 앵커 ID는 `doltap-<종류>-<식별자>`이며 종류는 d·s·b,
식별자는 Crockford Base32 소문자 8자(40비트)입니다. 문자 집합은
0123456789abcdefghjkmnpqrstvwxyz이며 crypto.randomBytes(5)로 후보를 만듭니다.
발급 대장과 실제 범위에서 충돌을 확인해 다시 뽑습니다.

```html
<a name="doltap-s-3q8m5k2p-start" id="doltap-s-3q8m5k2p-start"></a>
<a name="doltap-s-3q8m5k2p-end" id="doltap-s-3q8m5k2p-end"></a>
```

각 앵커는 독립된 줄에 두고 name과 id를 같게 씁니다. start/end로 범위를 감싸며
문서 d, 절 s, 작은 항목 b를 구분합니다. 범위 교차·ID 중복·b 안의 b는 오류입니다.
문서에는 d 범위 하나가 필요하며 범위 밖에 본문을 쓰지 않습니다.
링크는 #doltap-…-start로 씁니다. GitHub가 렌더링한 user-content- 접두사를
원문 링크에 넣지 않습니다. 지원 화면은 GitHub와 VS Code 기본 Markdown 미리보기입니다.

## 링크와 관계

관계는 백틱으로 감싼 유형 바로 뒤에 Markdown 링크를 둡니다.

```markdown
- `derived-from` [원본](source.md#doltap-d-3q8m5k2p-start)
```

관계의 출발점은 그 줄을 포함하는 가장 안쪽 범위입니다. 단순한 ID 링크도 관계
유형이 없으면 엣지가 아닙니다. 일반 링크는 파일 존재를 검사하고, 기존 제목 조각은
자동으로 ID 조각으로 바꾸지 않습니다. 관계에는 제목 조각 대신 ID 조각을 씁니다.
공백·# 등 경로 문자는 URI 인코딩합니다. 관계 ID는 출발:유형:도착이며, 대칭 관계는
두 ID를 사전순으로 정렬합니다. 같은 관계의 중복 선언은 오류입니다.

| 유형 | 역방향 | 대칭 | 만료를 일으키는 내용 |
| --- | --- | --- | --- |
| references | referenced-by | 아니오 | 없음 |
| indexes | indexed-by | 아니오 | 없음 |
| governs | governed-by | 아니오 | 없음 |
| imports | imported-by | 아니오 | 없음 |
| depends-on | required-by | 아니오 | 도착 |
| produces | produced-by | 아니오 | 출발 |
| verified-by | verifies | 아니오 | 양쪽 |
| derived-from | source-of | 아니오 | 도착 |
| decided-by | decides | 아니오 | 도착 |
| assumes | assumption-for | 아니오 | 도착 |
| supersedes | superseded-by | 아니오 | 없음 |
| related-to | related-to | 예 | 없음 |
| mirror-of | mirror-of | 예 | 검토 대신 내용 해시 일치 검사 |
| update-with | update-with | 예 | 양쪽 |

mirror-of는 정규화한 내용이 다르면 오류입니다. 번역이나 함께 갱신할 문서는
update-with로 검토합니다. 여러 출발점이 한 대상을 가리켜도 관계별 검토는 독립적입니다.

## 관리 범위와 발급

기본 범위는 AGENTS.md·CLAUDE.md·.doltap의 Markdown입니다. 운영 문서가 ID 관계로
직접 연결한 외부 Markdown도 포함합니다. 외부 문서에서 계속 재귀적으로 확장하지
않습니다. .git·node_modules·.svn·.hg·dist·build·coverage, 운영 폴더 이외의 숨김
폴더, .doltap/recovery와 심볼릭 링크는 탐색하지 않습니다. 외부 관계도 이 경계를
우회하지 않습니다. 연결된 외부 파일을 옮겼으면 ID로 일반 Markdown 후보를 찾습니다.

CLAUDE.md는 @AGENTS.md 한 줄입니다. 앵커 대신 특수 ID doltap-d-claude-md와
imports 연결을 계산합니다. mirror-of로 본문을 비교하지 않습니다.

ids.md의 열은 ID·종류·상태·경로·대체·삭제 이유입니다. 상태는 활성·아카이브·삭제입니다.
삭제한 행도 남겨 재사용을 막습니다. 재발급은 상태를 암묵적으로 바꾸지 않습니다.
새 아카이브는 처음부터 아카이브로 등록하며 중복 행은 첫 행으로 축약하지 않고 중단합니다.
배타적 잠금을 잡아 쓰며 잠금 내용 기록·닫기 실패 때 핸들과 불완전한 잠금을 정리합니다.
Windows의 잠금 open에서 EPERM이면 10ms 간격으로 최대 40회까지 시도합니다.
다른 주인의 잠금을 지우지 않으며, 지속 오류는 원래 오류로 전달합니다.

migrate는 기존 문서 ID를 유지하고 새 문서에 d ID와 구조 색인을 추가합니다.
제목·주장 범위를 추측하거나 의미 관계를 자동 생성하지 않습니다. 구형 .agents와
.doltap/project.md는 안내 후 이관하며 파일 충돌은 중단합니다. 처음 이관하는 옛
아카이브는 legacy로 구분하되 신규 아카이브를 반복 이관으로 legacy화하지 않습니다.

## 내용 해시와 검토

contentHash는 정규화한 본문의 SHA-256입니다. CRLF를 LF로 맞추고 앵커·관계 선언을
제외합니다. 일반 문단의 줄바꿈·연속 공백·빈 줄은 합치되 제목·목록·표·인용·구분선,
강제 줄바꿈과 중첩 목록 들여쓰기는 구분합니다. 코드 블록의 공백은 보존합니다.
일반 링크는 표시 이름과 대상의 정체를 남깁니다. 관리 대상이면 ID와 조각, 미등록
로컬 대상이면 저장소 기준 경로와 조각, 외부 대상이면 URL을 사용합니다.
자연어 의미가 같은지를 판정하는 정규화는 아닙니다.

graphHash는 자신의 나가는 관계를 유형:도착ID로 정렬하고 개행으로 이어 SHA-256을
계산합니다. 라벨과 경로는 넣지 않습니다. 상대의 관계 추가만으로 관계 검토가 연쇄
만료되지 않도록 관계 검토는 contentHash를 관찰합니다.

reviews/reviewed.md에 노드·관계별 최신 한 건만 덮어씁니다. 과거 해시 일치 기록을
찾아 재사용하지 않습니다. 노드 행은 시각·노드ID·contentHash·graphHash·판단·이유·주체,
관계 행은 시각·관계ID·출발해시·도착해시·판단·이유·주체입니다. 해시는 앞 8자를 저장해
대조합니다. 충돌 가능성이 있고 대규모 사용 한계는 실측하지 않았습니다.

노드 판단은 최신임·고쳐야 함, 관계 판단은 반영함·영향 없음·재검증함입니다.
이유와 주체(사람·에이전트)는 필수이며 영향 없음은 이유가 최소 10글자여야 합니다.
노드의 두 해시 또는 관계 유형이 관찰하는 쪽이 마지막 검토와 다르면 stale입니다.
A 검토 → B 변경·검토 → A 복원은 stale이며, B를 검토하지 않았다면 복원한 A는 fresh입니다.
메타데이터·삭제 범위는 노드 검토 대상이 아닙니다. 검토는 승인이나 참의 증명이 아닙니다.

연도별 구형 노드·관계 표는 첫 review에서 시각상 최신 한 건씩 옮기고 제거합니다.
동일 시각은 경로순으로 읽은 뒤 나중 행을 택합니다. 손상 표는 덮어쓰지 않습니다.
감사 제안은 연도별 파일에 누적합니다. 삭제된 관계의 마지막 행과 복구 백업을 자동으로
지우지는 않습니다. 첫 검토 파일 생성으로 색인이 바뀌면 변경 후 그래프의 해시를 기록합니다.

## 이동·삭제·복구

move-fix는 ID를 유지하며 관계의 경로와 발급 위치·상태를 맞춥니다. 이름과 ID가
중복되면 추측하지 않습니다. delete는 살아 있는 범위와 자식을 함께 다루고, purge·
tombstone은 외부 참조가 있으면 거부합니다. replace는 대상 ID의 명시 참조를 대체하고
삭제 표식과 supersedes를 남깁니다. 자식 ID의 참조는 각각 먼저 대체해야 합니다.

delete의 폴더 인수는 purge만 받습니다. 등록된 문서와 내부 관계를 하나의 범위로
삭제하고, 외부 관계 제거는 --drop-links로 명시합니다. 일반 링크·혼합 본문은 직접
정리합니다. 미등록 파일은 retained에 표시해 남기며 성공 뒤 빈 폴더만 정리합니다.
root와 관리 메타데이터를 포함한 폴더는 묶음 삭제하지 않습니다.

delete-fix는 이미 사라진 ID 또는 경로를 정리합니다. 이동·남은 파일·손상 앵커를
삭제로 오인하지 않도록 중단합니다. 독립된 관계 줄 제거는 --drop-links가 필요하며
사후 삭제 정리 이유를 대장에 남깁니다. 탐색 제외 위치까지 검색하지는 않습니다.

쓰기의 기본은 미리보기이고 --apply에서 적용합니다. 미리보기는 파일별로
---/+++ 경로와 @@ 시작 줄, 제거(-)·추가(+) 줄을 보여줍니다. JSON은 preview에
같은 diff를 담습니다. 모든 대상의 원본을 먼저
recovery/<실행ID>/files/<번호>.bak에 백업하고 manifest.json에 경로·이전/이후 해시를
기록합니다. prepared → success로 진행하며 실패 시 롤백, 강제 종료 시 recover를
안내합니다. 미완료 실행이 있으면 다른 쓰기를 막습니다. 복구 시 현재가 이전·이후
해시와 모두 다르면 충돌로 중단합니다. 성공 백업도 자동 삭제하지 않으며 --discard로
폐기합니다. prepared는 폐기할 수 없습니다. 복구 자료는 Git과 그래프에서 제외합니다.

묶음 삭제 복구는 본문과 필요한 부모 폴더를 만들지만 원래 빈 폴더는 보장하지 않습니다.
delete-fix 이전에 이미 지운 본문은 그 명령의 백업에 없으므로 되살릴 수 없습니다.

## 골격의 미완성 자리 검사

check는 AGENTS.md와 .doltap/ 아래의 Markdown에서 아직 채우지 않은 자리를
찾습니다. .doltap/archive/는 제외합니다. 줄 앞의 공백 뒤에 `<!-- 채우기:`,
`<!-- 고르기:`, `<!-- 확인 필요:`로 시작하는 표식을 세어 파일별로 확인 안내를
냅니다. `<!--` 뒤와 콜론 앞에도 공백을 허용합니다.

이 검사는 원문 각 줄의 시작을 검사합니다. 닫는 `-->`까지 해석하거나 코드 블록을
제외하지 않으므로, 코드 예시 안에서도 같은 줄 시작 형태이면 셉니다. 본문에서
낱말만 언급하거나 인라인 코드로 감싼 예시는 세지 않습니다. 남은 표식은 오류가
아닌 확인 항목이므로 이것만으로 종료 코드가 1이 되지는 않습니다.

이 주석은 미완성 자리를 찾는 표식이며, 아래 아카이브 검사의 본문 선언과는
목적과 문법이 다릅니다. 한쪽의 주석 처리 규칙을 다른 검사에 적용하지 않습니다.

## 아카이브 검사

전제·열린 질문·상태·이유 표식은 줄 첫머리의 단일 백틱으로 선언합니다. 선택적
목록 표식을 허용하고 코드·HTML 주석·인용·표의 예시는 아카이브 선언으로 세지 않습니다.
각 범위는 자식의 선언을 제외한 자기 선언만 판정합니다. 항목마다 범위와 상태를 나눕니다.
미해결은 오류, 해결은 통과, 이월은 작업 범위 밖 활성 노드의 직접 관계가 있어야 하며,
폐기는 같은 범위에 이유가 필요합니다. 관계 유형을 assumes로 제한하지는 않습니다.

decisions.md의 각 ## 절은 계속 유효 또는 이번만 표식 하나가 필요합니다.
이 결정 표식도 본문 선언으로 읽으며 HTML 주석 안에 감싸면 세지 않습니다.
계속 유효에는 원본 설명이 필요합니다. 검사는 원본의 실제 존재·내용까지 증명하지
않으므로 종료 전에 담당자가 대조합니다. legacy에는 현재 의미 규칙을 소급하지 않습니다.
archive-check는 폴더를 이동하지 않습니다. 공통 규칙과 전제는 활성 원본에 반영하고,
종료 시 current에서 빼고 history로 연결한 뒤 실제 이동과 move-fix를 수행합니다.

## 조회·감사·실행 경계

map의 schema는 doltap.map.v1이며 nodes·edges·contains·fileEdges·cycles를 냅니다.
context는 doltap.context.v1, 기본 depth 2·budget 4000이며 nodes·edges·omitted를
냅니다. budget은 본문 문자 수이고 ID·관계 등 JSON 메타데이터는 별도입니다.
루트와 깊이 1 본문을 예산 안에서 내고 깊이 2 이상은 메타데이터만 냅니다.
bodyTruncated와 omitted로 생략을 표시하며 body는 정규화 전 원문입니다.
노드 상태는 active·archived·legacy·deleted, 관계 검토 상태는 none·fresh·stale입니다.

audit는 doltap.audit.v1, 기본 budget 8000입니다. errors·reviewRequired·candidates·
suggestions·ambiguous·decisions·omitted를 나눕니다. 관계·상태·경로 필터를 적용하며
legacy는 --include-legacy에서 포함합니다. --changed는 최신 검토가 없거나 고쳐야 함인
본문을 고릅니다. 관리 메타데이터는 후보에서 제외합니다. 외부 감사는 자동 등록이 아닙니다.
CLI는 AI API를 호출하지 않으며 suggestions·ambiguous는 스스로 채우지 않습니다.

suggest의 열은 시각·제안ID·출발·관계·도착·근거·판정·판정이유·주체입니다.
제안ID는 출발ID@출발내용해시앞4자:유형:도착ID입니다. 반영·기각·보류를 이유와 함께
누적하며 반영은 실제 관계가 있을 때만 기록합니다. 호스트가 decisions를 참고합니다.
검토·기각 기록은 신원 인증이나 사용자 승인으로 쓰지 않습니다.
검토 명령은 대상 한 건을 받으며 전체를 일괄 승인하는 옵션은 없습니다.
