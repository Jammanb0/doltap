# 문서 그래프 기반 — 상태

> 배경과 완료 조건은 `README.md`, 단계와 검증 방법은 `plan.md`, 정한 것과 그
> 이유는 `decisions.md`에 있습니다. 여기는 지금 어디까지 왔고 다음이 무엇인지만
> 다룹니다.

## 작업 위치

| 항목 | 값 | 어떻게 정했나 |
| --- | --- | --- |
| 작업 위치 | `workstream/009-document-graph` | 사용자 지시 — "로컬 브랜치 하나 만들어서 진행하고" |
| 기준 브랜치 | `main` | 사실 확인 — 갈림점이 `main`의 `50cf939` |
| 반영 대상 브랜치 | `main` | 사용자가 이 대화에서 직접 확인 |
| 원격 작업 흔적 | 남기지 않음 — 원격 작업 브랜치·PR·병합 커밋 없음 | 관례 추론 — 006·007·008과 같음 |

**관례 추론으로 정한 값은 원격 작업 흔적 하나뿐입니다.** 세 질문을 하나씩 묻지
않은 것은 사용자가 작업 위치를 지시하면서 추가 허락이 필요 없다고 했기
때문입니다. 다르게 하려면 알려 주세요.

계획 커밋도 기준 브랜치가 아니라 이 브랜치에 둡니다. 그 이유와 대가는
`decisions.md`에 있습니다.

**받은 승인의 범위**

- 워크스트림 생성 — 받음 ("다음 대작업 세팅을 해야해. 진행해줘")
- 이 브랜치 안의 파일 변경과 로컬 커밋 — 받음 ("로컬 커밋을 승인하며")
- 반영 대상 브랜치를 `main`으로 확정 — 받음 ("반영 대상은 main이 맞다고 지금
  말해줄게")
- push — **받지 않음** ("푸시는 진행하지 말아줘")
- `main` 반영 — **받지 않음**
- 구현 착수 — **받지 않음.** 사용자가 세팅만 요청했고, 다른 에이전트의 검토를
  받은 뒤에 코드를 고치겠다고 했습니다
- 대작업 종료와 아카이브 — **받지 않음**
- 작업 브랜치 삭제 — **받지 않음**

## 현재 단계

세팅과 첫 검토 반영을 마쳤습니다. `plan.md`의 1단계에 들어가기 전입니다.

## 직전 완료

- 다른 에이전트의 검토에서 나온 지적을 반영했습니다. 완료 조건에는 있는데
  단계에 자리가 없던 이동 복구·참조 중 삭제 방지·아카이브 전 전제 처리를
  `plan.md` 7단계로 넣고 뒤 단계를 밀었습니다. 완료 조건은 초안에서 확정으로
  바꿨고, 막히는 범위와 작업 위치 근거의 표현을 고쳤습니다.
- 반영 대상 브랜치가 `main`이라는 것을 사용자에게 직접 확인받았습니다.
- 설계 기록의 상태 표기를 갱신했습니다. 「대작업을 열기 전」과 「현재 활성
  워크스트림은 없다」가 이제 사실과 달랐습니다.

## 다음 행동

사용자와 새 공개 이름을 정합니다 — `plan.md` 1단계. 다섯 값을 한 번에 정합니다.

이름을 기다리는 동안 2단계에서 이름에 의존하지 않는 항목(정규화 규칙, 관계
어휘, 렌더러 동작, 살아 있는 전제 문법)을 먼저 볼 수 있습니다. 다만 **구현
착수 승인을 아직 받지 않았습니다.**

## 검증

세팅 시점에 돌린 것입니다. 코드는 고치지 않았으므로 기준선 확인입니다.

| 확인 | 결과 |
| --- | --- |
| `npm test` | 42개 통과 |
| `node bin/cairn.mjs check template` | 문제 0, 확인 5 |
| `node bin/cairn.mjs check .` | 문제 0, 확인 0, 진행 중인 대작업 1개 |

`check template`의 확인 5개는 골격이 일부러 비워 둔 채우기 자리입니다. 손대지
않았고 이 대작업 전에도 같은 수였습니다.

## 막힌 점과 열린 질문

- **새 공개 이름이 정해지지 않았습니다. 이름에 의존하는 작업이 막혀 있습니다.**
  운영 폴더 이름 변경, 앵커 접두사, 불변 ID 발급, 그 ID를 문서에 넣는 일이
  여기 해당합니다 — `plan.md`의 5·6단계입니다. 2단계 형식 확정과 3단계
  파서·검사기는 이름과 무관하게 진행할 수 있습니다.
- **이 구조를 쓰는 외부 프로젝트가 있는지 확인되지 않았습니다.** 없다고
  단정하지 않습니다. 확인되지 않았다는 것과 없다는 것을 섞어 쓴 것이 007에서
  고친 실수입니다.
- 설계 기록의 미확정 항목 27개가 그대로 남아 있습니다. `plan.md` 2단계에서
  각각 확정·시험 대상·범위 밖으로 가릅니다.
- 가장 어려운 항목은 해시 계산이 아니라 정규화 규칙입니다. 잘못 정하면 서식만
  바꿔도 재검토가 쏟아지거나 중요한 변경을 놓칩니다. 소스만 읽어서는 오탐을
  다 찾지 못하고 실제 문서를 고치는 동안 드러납니다.
- `plan.md`의 3단계 아래는 형식이 확정되면 모양이 달라질 수 있습니다. 지금
  순서는 확정되지 않은 형식 위에 세운 것입니다.
