# 변경을 검토하고 판단 남기기

[사용 안내](README.md) · [일상 조회](daily.md) · [실행 방법](getting-started.md)

문서를 고치면 “다시 봐야 함”이 나올 수 있습니다. 도구는 변경을 발견했을 뿐
올바른 수정인지 판단하지 않았습니다. 먼저 관련 본문을 읽습니다.

```sh
doltap audit .doltap --changed --json
doltap context <노드-ID> --json
```

## 노드 검토와 관계 검토

| 확인한 것 | 기록할 것 |
| --- | --- |
| 이 글의 내용과 나가는 관계가 지금 맞다 | 노드 검토 |
| 근거의 변경이 이 글에 미치는 영향을 확인했다 | 관계 검토 |

```sh
doltap review <노드-ID> --node --as 최신임 --why "내용과 연결된 근거를 확인함" --actor 에이전트
doltap review <관계-ID> --as "영향 없음" --why "원본 변경은 이 규칙의 적용 범위 밖임" --actor 에이전트
```

관계 ID는 map의 edges[].id에 있습니다. 미리보기를 확인하고 실제로 읽은 대상만
--apply로 기록합니다. 노드 검토만으로 관계 검토가 끝나지는 않습니다.

노드 판단은 최신임·고쳐야 함, 관계 판단은 반영함·영향 없음·재검증함입니다.
사람이 직접 검토했다면 actor를 사람으로 적습니다. 영향 없음은 이유가 최소
10글자여야 합니다. 주체 표시는 신원을 인증하거나 사용자 승인을 대신하지 않습니다.

## 마지막 검토와 비교한다

reviewed.md에는 노드·관계마다 최신 한 건만 남습니다.

```text
내용 A 검토 → B로 변경 → B 검토 → A로 복원
                                  다시 검토 필요(stale)
```

마지막에 검토한 B와 지금의 A가 다르기 때문입니다. B를 검토하지 않고 A로
복원했다면 마지막 검토도 A여서 일치합니다. 어떤 옛 검토든 찾아서 재사용하지 않습니다.

여러 문서가 같은 근거를 depends-on으로 가리키면 근거 변경 시 각 관계가 만료됩니다.
하나만 다시 검토해도 나머지는 그대로 남습니다. references나 indexes처럼
검토 상태가 없는 탐색 관계는 해당하지 않습니다.

## 감사 제안의 판단 남기기

audit는 사람이 검토할 자료를 준비합니다. CLI가 AI를 호출해 관계를 제안하지 않습니다.
사람이나 호스트 에이전트가 제안을 검토한 뒤 판단을 기록할 수 있습니다.

```sh
doltap suggest <출발-ID> --to <도착-ID> --relation verified-by --evidence "검증 범위 대조" --as 기각 --why "이 시험은 다른 동작을 검증함" --actor 에이전트
```

미리보기 뒤 --apply로 기록합니다. 반영·기각·보류 판단은 연도별 파일에 누적되며
reviewed.md의 최신 검토와 별개입니다. 반영은 실제 관계가 존재할 때만 기록하므로
관계를 만들기로 했다면 먼저 link로 연결합니다. 도구가 제안을 자동 적용하지 않습니다.
