# 문서, 앵커와 관계

[사용 안내](README.md) · 다음: [대작업의 흐름](workstreams.md)

doltap은 프로젝트의 규칙과 작업 상태를 Markdown 파일에 남기고,
문서 사이의 연결이 유지되는지 확인하는 도구입니다. 문서가 원본이므로
CLI를 실행하지 않아도 읽을 수 있습니다. 별도의 서버나 데이터베이스는 없습니다.

## 왜 문서에 `<a>`가 붙나

제목은 고치거나 옮길 수 있습니다. ID는 그 글을 계속 구별하기 위한 이름입니다.
CLI가 발급한 ID를 앵커에 넣으면 제목과 위치가 바뀌어도 같은 글을 찾을 수 있습니다.

아래는 문법을 보여주는 예시입니다. 실제 ID는 `doltap id`로 만듭니다.

```markdown
<a name="doltap-s-3q8m5k2p-start" id="doltap-s-3q8m5k2p-start"></a>

## 배포 조건

시험을 통과한 변경을 배포한다.

<a name="doltap-s-3q8m5k2p-end" id="doltap-s-3q8m5k2p-end"></a>
```

빈 `<a>`는 실행되는 스크립트가 아닙니다. Markdown을 화면에 표시할 때 링크의
도착점이 되고, 검사기에는 글의 경계를 알려줍니다. `start`는 시작,
`end`는 끝입니다. 둘 사이를 한 **노드**로 읽어 내용과 관계를 계산합니다.
미리보기에서는 빈 태그 자체가 보이지 않습니다.

| ID 종류 | 범위 | 쓰는 때 |
| --- | --- | --- |
| d — document | 문서 전체 | 관리할 파일을 처음 등록할 때 |
| s — section | 제목과 그 아래 절 | 한 절을 따로 가리키거나 검토할 때 |
| b — block | 더 작은 문단·주장 | 특정 전제나 판단만 독립적으로 다룰 때 |

모든 문장에 ID를 넣을 필요는 없습니다. 문서 단위로 시작하고 필요한 부분만
좁힙니다. start/end는 짝으로 유지하고 ID를 복사해 다른 문서에 재사용하지 않습니다.
CLAUDE.md만은 특수 연결로 다루므로 `@AGENTS.md` 한 줄을 유지합니다.

## 그냥 링크와 관계는 어떻게 다른가

```markdown
[결정](decisions.md#doltap-d-3q8m5k2p-start)
- `decided-by` [결정](decisions.md#doltap-d-3q8m5k2p-start)
```

첫 줄은 독자를 위한 링크입니다. 두 번째 줄은 “이 글은 저 결정에 근거한다”는
뜻까지 명시합니다. 관계 유형과 ID가 붙은 두 번째 줄만 그래프의 연결로 계산합니다.
도구는 일반 링크의 뜻을 추측해서 관계로 만들지 않습니다.

관계는 그 줄을 감싸는 가장 작은 노드에서 출발합니다. 여러 문서가 같은 규칙을
가리킬 수도 있고, 한 문서가 여러 근거를 가리킬 수도 있습니다. 관계별 ID가 달라
검토도 각각 관리합니다. 역방향 연결은 계산하므로 양쪽에 같은 관계를 중복해서 적지 않습니다.

## 사람이 판단하고 도구가 기록한다

| 하는 일 | 담당 |
| --- | --- |
| 규칙·진행 상태·판단 이유 작성 | 사람 또는 호스트 에이전트 |
| 어느 문서를 연결하고 지울지 결정 | 사람 또는 호스트 에이전트, 프로젝트 승인 규칙에 따름 |
| ID 발급, 참조 검사, 파일 경로 수정 | doltap CLI |
| 검토한 내용의 해시 저장과 현재 내용 대조 | doltap CLI |
| 글이 참인지, 근거가 적절한지 판단 | 사람 또는 호스트 에이전트 |

해시는 내용을 비교하기 위한 지문입니다. 관련 내용이 바뀌면 다시 검토하라는 표시가
나옵니다. 그 표시가 내용의 오류를 확정하지도, 표시가 없다고 내용의 정확성을 보장하지도 않습니다.

## 자동으로 적히는 파일은 무엇인가

- `.doltap/ids.md`: 발급한 ID와 위치·상태입니다. 삭제 ID도 남겨 재사용을 막습니다.
- `.doltap/reviews/reviewed.md`: 대상마다 마지막 검토 한 건입니다.
  사람이 이유·판단·주체를 명령에 주면 CLI가 해시와 함께 덮어씁니다.
- `.doltap/reviews/연도.md`: 감사에서 제안한 관계를 반영·기각·보류한 판단입니다.
  검토 기록과 달리 누적됩니다.
- `.doltap/recovery/`: 쓰기 명령이 바꾸기 전 파일을 보관하는 로컬 복구 자료입니다.
  사람이 작성하는 작업 일지가 아닙니다.

같은 대상을 반복 검토하면 reviewed의 행 수는 유지됩니다. 새 ID·새 검토 대상·
감사 제안·백업이 생기면 자료는 늘 수 있습니다. 성공한 복구 자료도 자동 삭제하지
않으므로 결과 확인 뒤 [recover --discard](moving-deleting.md)로 정리합니다.
