# 프로젝트 이름

<!-- 채우기: 이 프로젝트가 무엇을 하는지 두세 줄 -->

이 파일은 이 저장소에서 일하는 사람과 AI 코딩 에이전트가 함께 따르는 규칙입니다.
긴 내용은 따로 문서를 두고, 여기서는 언제 무엇을 읽을지 안내합니다.

## 작업을 시작할 때

1. `.doltap/current.md`에서 진행 중인 작업을 찾습니다.
2. 이어받을 작업이 있으면 그 폴더의 `README.md`(목적·범위)와 `status.md`(현재 상태·재개
   지점)를 읽습니다. `plan.md`와 `decisions.md`는 있으면 필요한 만큼 읽습니다.
3. 작업이 도중에 끊겼다면 `status.md`의 마지막 기록과 실제 파일 변경을 대조한 뒤
   이어갑니다.

## 작업 기록

- 여러 단계나 여러 세션에 걸치는 작업은 `.doltap/workstreams/<세 자리 번호>-<영문 이름>/`에
  `README.md`와 `status.md`를 두고, `.doltap/current.md`에 링크를 적습니다.
- `status.md`에는 완료한 것, 진행 중인 것, 확인한 결과, 재개 지점, 막힌 점을 짧게
  적습니다. 의미 있는 작업 단위가 끝날 때마다 고칩니다. 마지막에 정리할 기회가 있다고
  기대하지 않습니다.
- 순서와 검증 방법을 미리 정해야 하면 `plan.md`, 나중에도 알아야 할 선택과 이유는
  `decisions.md`에 둡니다.
- 작업을 마치면 `.doltap/history.md`에 한 줄 남기고 폴더를 `.doltap/archive/`로
  옮깁니다. 앞으로도 적용할 내용이 작업 기록에만 남아 있다면 담당 문서에 반영합니다.

## 문서 사이의 관계

- `<!-- doltap:start … -->`와 `<!-- doltap:end … -->` 주석은 범위와 관계를 적은
  표식입니다. 문서를 고칠 때 표식의 ID를 바꾸지 않습니다. 범위를 통째로 지울 때는 표식도
  함께 지우고 `doltap check`로 남은 참조를 확인합니다.
- 관계가 있는 범위를 고쳤으면 `doltap check`를 실행하고, `doltap review`가 보여 주는
  상대 범위를 읽어 여전히 맞는지 확인합니다.
- 내용이 어긋나면 내용을 고치고, 관계를 잘못 적었으면 양쪽 선언을 고치거나 해제합니다.
  검사를 통과시키려고 관계를 느슨하게 바꾸지 않습니다.
- 실제로 확인한 관계만 `doltap review <ID> <ID> --note <확인한 내용> --by agent --apply`로
  기록합니다.
