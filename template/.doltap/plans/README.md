# 계획 문서

이 폴더는 진행 중인 대작업, 완료 기록, 아직 착수하지 않은 아이디어를 서로 섞지
않고 관리합니다. 프로젝트 전체가 무엇인지는 `.doltap/project.md`에 있습니다.

지금 무엇이 진행 중인지 보려면 `current.md`, 대작업을 시작하거나 마치려면
`workstreams.md`를 읽습니다.

## 문서 지도

| 파일 | 무엇을 담는가 |
| --- | --- |
| `.doltap/project.md` | 프로젝트 전체는 무엇인가 — 목적, 사용자, 책임 범위 |
| `current.md` | 진행 중인 대작업이 어디 있는가 |
| `workstreams.md` | 모든 대작업을 어떻게 운영하는가 — 판단 기준, 이름, 작업 위치, 시작·완료 절차 |
| `history.md` | 마친 대작업의 결과와 보관 위치를 찾는 짧은 색인 |
| `ideas.md` | 아직 착수를 약속하지 않은 기능과 개선 후보 |
| `workstreams/<번호>-<이름>/` | 대작업 하나의 문서 폴더 |
| `.doltap/archive/workstreams/` | 마친 대작업의 원문 기록 |

## 대작업 폴더 안의 문서

필수는 `README.md`와 `status.md` 둘뿐입니다. 나머지는 필요할 때만 만듭니다.

| 파일 | 무엇을 담는가 | 담지 않는 것 |
| --- | --- | --- |
| `README.md` | 이 대작업이 무엇인가 | 진행 상황, 다음 행동 |
| `status.md` | 지금 어디까지 왔는가 | 배경 설명, 단계별 작업 순서 |
| `plan.md` | 어떤 순서와 방법으로 할 것인가 | 진행 체크 |
| `design.md` | 상세 설계, 데이터 흐름, 검증 근거 | 진행 상황 |
| `decisions.md` | 중요한 결정과 그 이유 | 아직 정하지 않은 것 |

### `README.md`

- 한 줄 설명
- 배경과 시작 이유
- 범위와 제외 범위
- 완료 조건
- 작업을 이해하는 데 필요한 고정된 전제

시작할 때 정하고 잘 바뀌지 않는 것만 둡니다.

### `status.md`

- 작업 위치, 기준 브랜치, 반영 대상 브랜치, 원격 작업 흔적 여부
- 현재 단계
- 직전 완료
- 다음 행동
- 막힌 점과 열린 질문

누적 일지로 만들지 않습니다. 다음 세션에 필요한 현재 상태로 계속 갱신하고,
지나간 단계를 쌓아 두지 않습니다.

**이 파일은 그대로 아카이브에 남습니다.** 그래서 마칠 때 완료 또는 취소 상태로
마지막 갱신을 합니다. 무엇을 적는지는 `workstreams.md`의 「마칠 때」에
있습니다.

### `plan.md`

아래 중 하나에 해당할 때만 만듭니다.

- 작업 순서를 미리 정해야 한다.
- 단계 사이에 선행 관계가 있다.
- 조건에 따라 진행 방향이 갈린다.
- 단계별 검증 방법을 미리 정해야 한다.
- 계획 없이 바로 진행하면 범위나 방법이 흔들릴 가능성이 있다.

`README.md`의 완료 조건과 `status.md`의 다음 행동만으로 진행할 수 있으면
만들지 않습니다. 빈 틀만 남습니다.

만든다면 이것을 담습니다.

- 단계별 작업 순서
- 단계별 검증 방법
- 선행 조건

진행 체크 문서가 아닙니다. "현재 4단계" 같은 진행 정보는 `status.md`가
담당합니다. 계획은 대체로 그대로 유지하되, 실제 계획이 바뀌면 이 파일을 고치고
중요한 변경 이유는 `decisions.md`에 남깁니다.

## 읽는 순서

일상적인 이어받기에 필요한 것은 셋뿐입니다.

1. 지난 작업을 이어받을 때는 `current.md`.
2. 그 대작업을 처음 접하면 폴더의 `README.md`로 배경과 범위를 이해합니다.
3. 이어서 작업할 때는 같은 폴더의 `status.md`를 읽습니다.

나머지는 필요할 때만 읽습니다.

- 순서와 검증 방법이 필요하면 그 폴더에 `plan.md`가 있을 때 읽습니다.
- 무엇이 왜 정해졌는지가 필요하면 그 폴더에 `decisions.md`가 있을 때 읽습니다.
- 대작업을 새로 만들거나, 운영 방식을 바꾸거나, 완료·취소를 처리할 때만
  `workstreams.md`를 읽습니다. 평범한 이어받기에는 필요하지 않습니다.
- 프로젝트 전체 방향을 확인할 때만 `.doltap/project.md`를 읽습니다.
- 아직 착수하지 않은 후보는 `ideas.md`, 마친 작업은 `history.md`에서 찾습니다.

## 문서를 쓸 때

- 같은 상태를 두 파일에 반복해서 적지 않습니다. `current.md`는 위치만 가리키고,
  상세 상태는 `status.md`가 가집니다. 어디로 옮겼는지 가리키기만 하는 한 줄은
  중복이 아닙니다 — 그 줄에 어느 쪽이 원본인지 적혀 있으면 이정표입니다.
- 같은 폴더의 파일은 파일명으로 줄여 쓰고, 다른 폴더의 파일을 가리킬 때는
  저장소 루트 기준 경로와 `/`를 사용합니다.
- 계획 문서에는 코딩 규칙이나 도메인 지식을 다시 기록하지 않습니다. 관련
  원본은 저장소 `AGENTS.md`의 문서 안내표를 따릅니다.
