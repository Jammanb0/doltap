# 검증

작업을 완료했다고 보고하기 전에 아래 기준으로 확인합니다.

- 보고할 내용이 현재 코드, 파일과 명령 출력에 맞는지 확인합니다. 추측이나
  기억으로 답하지 않습니다.
- 코드를 바꿨으면 아래 명령을 실행합니다.
<!-- 채우기: 이 프로젝트의 타입 체크·린트·테스트·빌드 명령
     예) `npm run typecheck`, `npm test` / `pnpm lint`, `pnpm build` -->
- 화면에 보이는 것을 바꿨으면 실제로 띄워서 확인합니다. 타입 체크와 린트 통과는
  기능이 동작한다는 뜻이 아닙니다.
- 실행하지 못한 것은 실행했다고 쓰지 않습니다. 확인하지 못한 항목과 그 이유를
  밝힙니다.
- 되돌릴 수 없는 작업(삭제, 덮어쓰기, 원격 반영) 전의 확인 명령이 실패하면
  확인되지 않은 것으로 봅니다. 내가 손대지 않았다는 것을 변경이 없다는 근거로
  삼지 않습니다. 확인될 때까지 실행하지 않고 무엇을 확인하지 못했는지 밝힙니다.
- 링크는 실제 요청 결과를 확인하지 않았으면 유효하다고 쓰지 않습니다.
- 예시 코드는 실행하지 않았으면 실행된 코드라고 쓰지 않습니다.
- CI 설정을 바꿨으면 설정 파일만 읽고 운영 실행까지 검증했다고 표현하지
  않습니다. 실제 실행 여부와 로컬 검증을 구분해서 씁니다.
- 자동 검사 통과를 사실 확인 완료로 표현하지 않습니다.
- 스테이징 전 실제 diff를 확인하고 시크릿, 개인정보, 불필요한 생성물이 들어가지
  않았는지 확인합니다.
- 밖으로 보여지는 글은 실제 상태나 기여보다 부풀리지 않습니다. 정확하고 검증
  가능하며 방어할 수 있는 표현을 씁니다.
- 규칙, 경로, 절차를 바꿨으면 저장소 전체에서 관련 표현을 검색해 안내문, 예시,
  템플릿에 이전 내용이 남아 있지 않은지 확인합니다. 고친 파일만 보지 않습니다.
- 지적받은 항목은 하나씩 어디를 어떻게 고쳤는지 대조한 뒤 해결 여부를
  판단합니다. 파일을 고친 것만으로 해결됐다고 보고하지 않습니다.
- 확인한 범위까지만 씁니다. 앞 단계가 통과했다고 그다음 단계까지 통과한 것으로
  넓히지 않습니다.
- 보고에 쓰는 파일 내용, 숫자, 도구 동작은 원본이나 실행 결과와 대조합니다.
  이전 답변을 근거로 삼지 않습니다.
