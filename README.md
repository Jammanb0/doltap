# doltap

**세션이 바뀌어도, 이어갈 자리는 남도록.**

[English](README.en.md) · [사용 안내](docs/guide/README.md) · [기존 프로젝트에 적용](APPLY.md) · [검증 기록](https://github.com/Jammanb0/doltap/blob/main/docs/verification/README.md)

## 이런 일, 겪어보셨나요

AI와 무언가를 만들다가 다음 날 새 대화를 열면, 어제 하던 일을 다시 설명해야 할 때가 있습니다.

> “우리는 이렇게 하기로 했어. 코드를 바꾸기 전에 계획부터 보여줘.”
>
> “지금 로그인 기능을 만들고 있었는데, 어디까지 했냐면…”
>
> “그걸 왜 그렇게 만들었냐면, 예전에 이런 문제가 있어서…”

규칙은 다시 말할 수 있습니다. 어디까지 했는지도 파일을 열어 보면 어느 정도 떠오릅니다.
그런데 **왜 그렇게 정했는지**는 찾기가 어렵습니다. 결과물은 남아 있어도 이유는 지난 대화
중간에 묻혀 있고, 시간이 지나면 나도 정확히 기억하지 못합니다.

문서가 늘면 다른 문제도 생깁니다. 한국어 안내를 고쳤는데 영어 안내는 그대로이거나, 지원
환경 규칙이 바뀌었는데 그 규칙을 보고 쓴 설치 안내는 예전 내용이거나, 사용자 안내와 운영
절차가 서로 다른 방법을 말하게 됩니다. 한쪽만 고쳤다는 사실은 쉽게 눈에 띄지 않습니다.

이런 내용을 대화에만 두지 않고 **프로젝트 안의 문서로 남기고, 함께 맞아야 하는 문서끼리
이어 두면** 어떨까요? 새로 작업을 시작하는 AI가 그 문서에서 규칙과 지금 하던 일을 찾고,
문서를 고친 뒤에는 함께 확인해야 할 곳을 알 수 있도록요.

doltap은 그 기록을 둘 자리를 정하고, 이어진 문서가 어긋나지 않았는지 확인하는 도구입니다.

## 그래서 뭘 하는 도구인가요

두 가지를 합니다.

- **이어갈 자리를 남깁니다.** 항상 지킬 규칙은 `AGENTS.md`에, 진행 중인 작업은
  `.doltap/current.md`와 작업별 상태 문서에 둡니다. 새 세션이 이 문서들부터 읽도록
  `AGENTS.md`가 안내합니다.
- **이어진 문서를 확인합니다.** 번역처럼 같아야 하는 부분, 기준과 그것을 따르는 부분,
  서로 맞물려야 하는 부분을 관계로 이어 두면, 한쪽이 바뀌었을 때 다시 볼 곳과 구성이
  어긋난 곳을 알려 줍니다.

이런 기록은 **함께 작업하는 AI에게 맡길 수 있습니다.** 프로젝트 파일을 읽고 고칠 수 있는
데스크톱 앱이나 터미널의 AI에게 요청하는 방식입니다. 직접 명령을 실행해도 됩니다.

~~~text
이 프로젝트의 규칙과 현재 작업 기록을 읽고, 이어서 할 일을 확인해줘.
문서를 고쳤으면 doltap check로 함께 확인할 곳을 보고, 작업 기록도 정리해줘.
~~~

기록은 Markdown이라는 일반 텍스트 문서로 남습니다. doltap을 실행하지 않아도 열어 읽고
고칠 수 있고, doltap을 계속 켜 두거나 AI API 키를 등록할 필요도 없습니다.

## 이렇게 씁니다

한국어와 영어 설치 안내가 있다고 해 봅시다. 두 문서의 해당 부분에 화면에는 보이지 않는
표식을 달고 "같은 내용을 유지해야 한다"는 관계를 적어 둡니다.

~~~markdown
<!-- doltap:start doltap-s-e3f0emcv
same-as: doltap-s-4txkm0y0
-->
## 설치 조건

Node.js 22 이상이 필요합니다.
<!-- doltap:end doltap-s-e3f0emcv -->
~~~

나중에 영어 안내에만 지원 운영체제를 하나 더했다면 `doltap check`가 이렇게 알려
줍니다(일부 줄임). 첫 항목은 두 부분의 구성이 달라졌다는 문제(글머리 목록 4항목과 3항목)이고,
두 번째는 지난 검토 뒤 한쪽이 바뀌었으니 다시 확인하라는 안내입니다.

~~~text
✗ 문제 1개
  [SAME_AS_SKELETON] docs/en/install.md:12
    same-as 골격이 다릅니다: 3번째 요소 — …는 글머리 목록 4항목, …는 글머리 목록 3항목
! 확인 1개
  [REVIEW_PENDING] docs/en/install.md:5
    지난 검토 뒤 …가 바뀌었습니다. …와 여전히 같은 의미와 골격인지 확인하세요
~~~

사람이나 AI가 두 부분을 읽고 맞추면, 무엇을 확인했는지 검토 기록으로 남깁니다. 뜻이 실제로
같은지는 doltap이 아니라 읽은 사람이나 AI가 판단합니다.

## 내 프로젝트에 써 보려면

이미 작업 중인 프로젝트가 있다면, 함께 쓰는 AI에게 doltap의 [적용 절차](APPLY.md)와 대상
프로젝트의 위치를 알려 주고 요청할 수 있습니다.

~~~text
APPLY.md를 읽고 이 프로젝트에 doltap을 적용하는 변경안을 먼저 보여줘.
기존 규칙과 기록은 보존하고, 모르는 것은 추측하지 말고 물어봐줘.
~~~

처음부터 새 프로젝트로 시험해 보려면 Node.js 22 이상이 필요합니다. 아래는 Git으로 소스를
받는 방법입니다.

~~~sh
git clone https://github.com/Jammanb0/doltap
cd doltap
~~~

받은 소스 폴더에서 다음 두 명령을 실행합니다. 별도 패키지 설치나 빌드 단계는 없습니다.

~~~sh
node bin/doltap.mjs init ../my-project
node bin/doltap.mjs check ../my-project
~~~

첫 줄은 옆에 `my-project` 폴더를 만들고 기본 구조를 넣고, 두 번째 줄은 그 구조를
검사합니다. 처음에는 프로젝트에 맞게 채울 자리가 있다고 안내합니다. 관계를 잇고 검토하는
과정까지 따라 해 보려면 [시작하기](docs/guide/getting-started.md)를 보세요.

## 문서가 놓이는 곳

| 위치 | 역할 |
| --- | --- |
| `AGENTS.md` | 사람과 AI가 따르는 규칙, 작업을 시작할 때 읽을 곳 |
| `.doltap/current.md` | 지금 진행 중인 작업이 어디 있는지 |
| `.doltap/workstreams/` | 작업별 목적과 범위, 현재 상태와 다시 시작할 지점 |
| `.doltap/history.md` · `.doltap/archive/` | 마친 작업을 찾는 목록과 당시의 기록 |
| `.doltap/reviews.json` | 관계마다 마지막으로 확인한 기록 |

폴더 이름을 외울 필요는 없습니다. 어떤 문서를 언제 읽을지는 `AGENTS.md`가 안내하고, 지금
하는 일은 `current.md`에서 찾습니다. 작업 폴더와 보관 폴더, 검토 기록은 필요해질 때 생깁니다.

## 확인할 수 있는 범위

검사기는 표식이 올바른지, 관계의 양쪽이 서로를 가리키는지, 같아야 하는 부분의 구성이
같은지, 마지막 검토 뒤 내용이 바뀌었는지, 링크가 끊겼는지, 진행 중인 작업이 목록에 있는지를
확인합니다.

글의 내용이 참인지, 번역의 뜻이 같은지, 연결한 근거가 적절한지, AI가 실제로 지시를 잘
따랐는지까지 판단하지는 않습니다. 그 부분은 사람과 AI가 내용을 읽고 검토합니다.

doltap 1.0.0을 무엇으로 어떻게 확인했는지는
[검증 기록](https://github.com/Jammanb0/doltap/blob/main/docs/verification/README.md)에 있습니다.

## 1.0에 대해

doltap은 0.1부터 0.4까지(2026년 9월) 자기 자신에게 적용해 운영하며 문서 지도, 문서 ID
대장, 삭제·복구 명령, 단계마다 승인받는 작업 절차 같은 여러 기능과 작업 방식을 시험했습니다.
1.0은 그 경험을 바탕으로 이어갈 자리, 문서 사이의 관계, 검토 기록에 집중해 새로 시작한
버전입니다. 단계마다 승인받는 작업 절차는 [작업 방식 예시](docs/guide/work-style.md)에서 골라 쓸 수
있습니다.

doltap은 산길에 쌓는 돌탑에서 따온 이름입니다. 다시 온 사람이 어디까지 왔는지 찾을 수 있도록 기록을 남깁니다.
