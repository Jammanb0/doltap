# 검증과 시험 기록 개편

`0.2` 구조가 실제로 굴러가는지 한 흐름으로 확인하고, 그 결과로
`docs/trials/README.md`를 현재 검증 범위와 알려진 제한 중심으로 다시 씁니다.

## 배경

`0.2`에서 검증된 것은 주로 파일 구조와 검사기입니다. 시험 34개와 여섯 CI
조합이 `init`·`check`를 고정하고 있습니다. 정작 cairn이 파는 것 — 에이전트가
새 구조를 이해하고 이어서 일하는가 — 는 아직 `0.1.x` 구조를 대상으로 한
기록뿐입니다. 그 기록이 가리키는 옛 루트 문서는 이제 없습니다.

시험 기록 문서 자체에도 문제가 있습니다. 411줄에 세 역할이 섞여 있습니다.

```text
1~6번   지나간 버전의 시험 일지 (문서 스스로 고치지 않는다고 선언)
7번     현재 버전의 검증 보고
「아직 확인하지 않은 것」  5번 시점 스냅숏 — 204행, 문서 한가운데
「앞으로 검증할 것」       살아 있는 목록 — 385행, 맨 끝
```

같은 사실이 서로 다른 시점으로 세 곳에 적히니 어긋납니다. 실제로 README가
"세 운영체제 CI를 돌린다"고 쓰고 바로 아래에서 그 스냅숏을 가리켰는데, 스냅숏은
운영체제를 미검증으로 적고 있었습니다. 서식이 모순을 만든 것이 아니라, 모순을
만들 수밖에 없는 서식입니다.

## 이 작업의 범위

- 임시 기존 프로젝트에 `0.2`를 적용하고, 워크스트림을 열어 일부 진행한 뒤,
  맥락 없는 새 세션이 이어받아 마무리까지 가는 한 흐름을 실제로 돌립니다.
- 그 한 흐름에서 아래를 함께 봅니다.
  - 새 세션이 `current.md` → `README.md` → `status.md`를 찾아가는가
  - 평범한 이어받기에 `workstreams.md`부터 통째로 읽지 않는가
  - `직전 완료`가 교체되고 누적되지 않는가
  - 단순한 작업에 `plan.md`를 만들지 않는가
  - 기존 규칙과 기록이 보존되는가
  - 시작할 때 정한 브랜치 결정을 다시 묻지 않는가
  - 허락 전에 아카이브하지 않고 먼저 제안하는가
- `docs/trials/README.md`를 현재 검증 범위와 알려진 제한 중심으로 다시 씁니다.
- `README.md`와 `README.en.md`가 검증 범위를 넘어 주장하는 문장을 고칩니다.

## 제외 범위

- **완전한 보장을 목표로 하지 않습니다.** 모델 행동은 실행마다 달라서 몇 번
  통과해도 다음 실행을 보장하지 않습니다. 확인하려는 것은 기본 흐름이 실제로
  가능한지, 문서끼리 모순되지 않는지, 대표적인 실패가 무엇인지입니다.
- 원격 브랜치·push·PR·병합 흐름은 이번에 다루지 않습니다.
- `.agents/`를 커밋하지 않는 프로젝트, 동시 워크스트림, `0.1.x` 실이관은 이번에
  다루지 않습니다.
- 릴리즈(`v0.2.0` 태그와 GitHub Release)는 만들지 않습니다.
- 검사기의 알려진 오탐 두 가지는 고치지 않습니다. `ideas.md`에 후보로 두고,
  이번에는 알려진 제한으로 기록만 합니다.

## 완료 조건

- 임시 프로젝트에서 적용부터 마무리까지 한 흐름을 실제로 돌렸고, 각 항목의
  통과·부분 통과·실패와 함께 그 판정의 근거와 근거 수준을 구분해 기록했다.
- 맥락 없는 세션이 새 구조에서 진행 상태를 찾아 답하는지 확인했다.
- `docs/trials/README.md`가 현재 `main` 기준으로 확인된 것과 알려진 제한만
  담고, 지나간 시점의 목록이 남아 있지 않다.
- 두 README가 검증 범위를 넘어 주장하지 않는다. `기존 파일은 하나도 건드리지
  않습니다`처럼 적용 절차와 어긋나는 문장이 없다.
- `npm test`, `check template`, `check .`가 통과한다.

## 전제

- 이 세션은 Claude Code입니다. Codex를 직접 실행할 수 없으므로 "다른 도구의 새
  세션"은 이번에 대신할 수 없습니다. 맥락 없이 시작하는 별도 에이전트를 쓰되,
  그것이 Codex 검증이 아니라는 것을 기록에 분명히 남깁니다.
- 판정 근거는 항목마다 구분해서 밝힙니다. 파일 상태, 명령 출력, 실제 도구 호출
기록을 우선하고, 에이전트의 자기 보고에 기댄 항목은 그 사실을 함께 적습니다.

## 문서

- 현재 상태와 다음 행동: `status.md`
- 단계와 검증 방법: `plan.md`
- 정한 것과 그 이유: `decisions.md`
