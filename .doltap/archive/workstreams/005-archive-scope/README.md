# 대작업: 아카이브 검사 범위

검사기가 아카이브 안의 문서를 읽지 않도록 범위를 좁힙니다.

## 배경

아카이브는 지나간 기록입니다. 그때의 경로와 그때의 판단을 그대로 담고 있는
것이 정상이고, 관리는 사용자에게 맡기는 것이 원래 의도였습니다.

그런데 지금 `cairn check .`가 내는 확인 10개가 전부 아카이브에서 나옵니다.

- 끊긴 옛 경로 6곳. 아카이브니까 끊기는 것이 정상입니다.
- `.cairn` 언급 4개 문서 12곳. 적용 과정을 기록한 자리라 정확한 기록입니다.

고칠 수 없거나 고칠 필요가 없는 것을 매번 알리고 있고, 아카이브가 늘수록 함께
늘어납니다. 그러다 진짜 봐야 할 확인이 묻힙니다.

`.cairn` 검사는 코드가 자기 주석과도 어긋납니다. 주석에는 「활성 문서가
가리키는지」라고 적어 놓고 아카이브까지 훑습니다.

번호 검사도 지금은 아카이브끼리의 충돌과 아카이브 폴더 이름 형식까지 봅니다.
활성 쪽 실수를 잡으려던 검사가 아카이브 관리로 번졌습니다. 활성과 아카이브가
겹칠 때 오류 위치가 아카이브 쪽으로 표시되기도 합니다.

## 이 작업의 범위

- 아카이브 안의 문서를 검사 대상에서 뺍니다. 링크, `.cairn` 참조,
  자리표시자가 해당합니다.
- 아카이브 폴더 이름 형식을 평가하지 않습니다.
- 아카이브끼리의 번호 충돌을 잡지 않습니다.
- 새 활성 워크스트림이 지난 번호를 다시 쓰는 것만 아카이브 폴더 이름으로
  확인하고, 그때 오류 위치는 활성 폴더입니다.
- 바뀐 동작을 시험으로 고정합니다.
- 두 README의 설명을 맞춥니다.

## 제외 범위

- 아카이브를 정리하거나 지우는 기능을 만들지 않습니다. 관리는 사용자 몫입니다.
- `history.md`가 없어진 아카이브를 가리키는 것은 계속 문제로 잡습니다.
  `history.md`는 활성 문서이고, 색인과 실물이 어긋난 것은 활성 쪽 결함입니다.
- 검사에서 뺀다는 것이 폴더를 지워도 된다는 뜻은 아닙니다. 아카이브 폴더
  이름은 검사기가 과거에 사용한 번호를 판단하는 기준입니다.
- **활성 문서가 임시 골격 이름을 말로 설명할 때 나는 오탐은 이번에 고치지
  않습니다.** 7번 검사는 줄에 그 이름이 들어 있기만 하면 잡으므로, 검사기를
  설명하는 활성 문서가 그대로 걸립니다. 이 워크스트림의 문서와 `ideas.md`가
  실제로 걸렸습니다. 아카이브와 원인이 다르고 판정 방식을 새로 정해야 해서
  따로 다룹니다.

## 완료 조건

- `cairn check .`의 확인에서 **아카이브가 원인인 것이 0개**다. 활성 문서가
  임시 골격 이름을 설명해서 나는 확인은 위의 제외 범위라 남습니다.
- 아카이브만 있고 활성 워크스트림이 없는 프로젝트도 문제 0으로 통과한다.
- 활성이 아카이브 번호를 다시 쓰면 **활성 폴더 자리에서** 문제로 잡는다.
- 아카이브끼리 번호가 겹치거나 이름이 형식에 어긋나도 아무것도 내지 않는다.
- `history.md`가 없어진 아카이브를 가리키면 문제로 잡는다.
- 두 README에 아카이브를 검사한다는 설명이 남아 있지 않다.
- `npm test`와 `cairn check template`이 통과한다.

## 전제

- 아카이브 폴더 이름은 검사기가 과거에 사용한 번호를 판단하는 기준입니다.
- 이 변경은 검사를 느슨하게 만듭니다. 지금까지 확인으로 알리던 것을 아예 알리지
  않게 되므로, 무엇을 잃는지 `decisions.md`에 적습니다.

## 문서

- 현재 상태와 다음 행동: `status.md`
- 단계와 검증 방법: `plan.md`
- 무엇을 왜 정했는지: `decisions.md`
