# 첫인상과 군더더기 — 계획

> 배경과 완료 조건은 `README.md`, 지금 몇 단계인지는 `status.md`에 있습니다.
> 여기는 순서와 검증 방법만 다룹니다.

README가 두 벌이라 단계마다 한국어와 영어를 함께 봅니다. 한쪽만 고치면
갈라집니다.

## 1. 살릴 내용을 먼저 옮긴다

0.1.x 절 안에 아카이브 취급 설명이 섞여 있습니다. 지금도 맞는 내용이라 지우기
전에 먼저 옮깁니다. 담긴 것은 셋입니다.

- 이미 아카이브한 기록은 그대로 두고, 검사기는 아카이브 안을 보지 않는다.
- 폴더 이름만 읽어서 지난 번호 재사용을 잡고, 고칠 곳은 새로 만든 쪽이다.
- 폴더를 지우면 `history.md`의 줄도 함께 지워야 한다.

「아카이브는 어떻게 다루나요」 같은 별도 질문으로 세웁니다.

**검증**

- 세 항목이 README 두 벌에 모두 남았는지 대조

## 2. 0.1.x 안내를 README 두 벌에서 뺀다

「0.1.x 를 쓰고 있었는데요」와 「I'm on 0.1.x — what changed?」 절을 지웁니다.
1단계에서 옮긴 내용이 빠지지 않았는지 확인한 뒤에 합니다.

**검증**

- 두 README에서 `0.1` 검색 결과가 없는지 확인
- 두 README의 질문 개수와 순서가 서로 같은지 확인

## 3. 루트와 `template/`의 구분을 README 두 벌에 넣는다

「들어 있는 것」 절이 자연스러운 자리입니다. 지금은 구조만 나열하고 그것이
어디서 오는지 말하지 않습니다. 두 가지를 적습니다.

- 그 구조는 `cairn init`이 만들어 주는 것이고 원본은 `template/`이다.
- 이 저장소 루트의 `AGENTS.md`와 `.agents/`는 배포물이 아니라 cairn을 자기
  자신에게 적용한 운영 문서다.

**검증**

- 두 README에 같은 뜻이 들어갔는지 대조

## 4. 검사기에서 0.1.x 감지를 뺀다

`lib/check.mjs`에서 지웁니다.

- `LEGACY_ROOT` 상수와 그것을 도는 2번 검사
- `LEGACY_WORKSTREAM` 상수와 활성 워크스트림에서 그 파일을 찾는 부분
- 위 둘만 쓰던 `legacy` 카운터

`legacy` 카운터가 3번 검사(`if (!missing && !legacy)`)에 얽혀 있으므로 그 조건도
함께 정리합니다. 지우고 나면 필수 문서가 없을 때만 알리게 됩니다.

**검증**

- `node --check` 대신 실제로 `cairn check`를 돌려 동작 확인
- 0.1.x 구조를 만들어 두고 무엇을 알리는지 눈으로 확인 — 「필수 문서가
  없습니다」로 나오는 것이 맞는지

## 5. 시험을 함께 정리한다

`test/check.test.mjs`에서 0.1.x 감지를 지키던 시험을 뺍니다. 다섯 개입니다.

- 이전 루트 `workflow.md`를 만나면 어디로 나뉘었는지 알린다
- 이전 `goal.md`를 만나면 `project.md`로 옮기라고 알린다
- 활성 워크스트림의 `workflow.md`를 만나면 셋으로 나뉘었다고 알린다
- 아카이브에 남은 `workflow.md`는 그때의 기록이라 잡지 않는다
- 출력 순서에서 이전 구조 안내가 먼저 나온다

넷째는 「잡으면 안 되는 쪽」이라 아깝지만, 잡을 코드가 없어지면 지킬 것도
없어집니다. 다섯째는 출력 순서 시험이라 다른 항목으로 같은 것을 볼 수 있는지
먼저 봅니다.

**검증**

- `npm test` 통과
- 남은 시험 수를 세어 `docs/trials/README.md`의 숫자와 맞춤

## 6. `docs/trials/README.md`를 맞춘다

- 「검증하지 않는 것」의 `0.1.x` 이관 항목을 뺍니다. 지원을 접었으므로 제외
  범위로 적을 것 자체가 없어집니다.
- 자동 검증 표의 시험 개수를 실제 값으로 고칩니다.

**검증**

- 문서에 적힌 숫자와 `npm test` 출력을 대조

## 7. 전체 검증

```bash
npm test
node bin/cairn.mjs check template
node bin/cairn.mjs check .
```

`template/`은 이번에 고치지 않지만 검사기가 바뀌므로 함께 돌립니다. `cairn init`
왕복도 확인합니다.

`0.1` 과 `workflow.md`, `goal.md` 를 검색합니다. **지금 쓰는 법을 설명하는
README와 제품 코드·시험에** 남은 안내가 없는지 보는 것이 목적입니다. 아카이브,
이 대작업의 작업 기록, `history.md`, `docs/trials`의 제외 범위 언급은 지나간
기록이거나 일부러 쓴 것이므로 걸려도 그대로 둡니다. 걸린 곳을 세어 "없다"고
쓰지 말고, 어느 범위에서 없는지를 적습니다.

## 선행 조건

- 1단계가 2단계보다 먼저입니다. 살릴 내용을 옮기기 전에 지우면 잃습니다.
- 4단계가 5단계보다 먼저입니다. 코드를 지워야 어떤 시험이 실제로 깨지는지
  확인하고 지울 수 있습니다.
