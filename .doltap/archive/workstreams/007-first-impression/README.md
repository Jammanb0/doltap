# 첫인상과 군더더기 — 소개

처음 보는 사람이 무엇을 받는지 헷갈리지 않게 하고, 외부 사용이 확인되지 않은
옛 이관 안내를 걷어냅니다.

## 배경과 시작 이유

두 가지가 겹칩니다.

**첫째, 저장소 루트와 `template/`이 헷갈립니다.** 이 저장소는 자기 자신에게
cairn을 적용해 운영합니다. 그래서 루트에 채워진 `AGENTS.md`와 `.agents/`가
있고, 배포되는 빈 골격은 `template/`에 따로 있습니다. 처음 보는 사람은 어느
쪽이 "내가 받을 것"인지 알기 어렵습니다.

같은 구조를 쓰는 다른 저장소를 확인했습니다. `github/spec-kit`은 `templates/`와
자기 적용본 `.specify/`를 함께 두고, `cline/cline`은 `.clinerules/`·`.claude/`·
`.codex/`·`.agents/`를 동시에 둡니다. `openai/codex`도 `.codex/`를 남깁니다.
**확인한 저장소들은 자기 적용 문서를 그대로 남기고 있었습니다.** spec-kit은
대신 자기 `AGENTS.md` 첫 문단에서 이 프로젝트가 무엇인지부터 설명합니다.
지우는 게 아니라 안내로 푸는 문제로 보입니다.

**둘째, 외부 사용이 확인되지 않은 0.1.x 이관 안내가 자리를 차지합니다.** 검사기에
`LEGACY_ROOT`·`LEGACY_WORKSTREAM`이 있고, README 두 벌에 접힘 절이 있고,
`docs/trials/README.md`에 제외 범위 항목이 있습니다. 그런데 0.1.x는
2026-09-06에 나와 2026-09-09에 0.2.0으로 대체됐고, 저장소는 스타·포크·이슈·PR이
모두 0입니다. 쓰던 사람이 있다는 증거가 없습니다.

## 범위

- README 두 벌에 루트와 `template/`의 구분을 명시합니다.
- 0.1.x 이관 안내를 걷어냅니다. `lib/check.mjs`의 `LEGACY_ROOT`와
  `LEGACY_WORKSTREAM`, 그것을 지키던 시험, README 두 벌의 0.1.x 절,
  `docs/trials/README.md`의 제외 범위 항목입니다.
- 0.1.x 절 안에 섞여 있던 **아카이브 취급 설명은 살립니다.** 0.1.x와 상관없이
  지금도 맞는 내용이라 다른 자리로 옮깁니다.

## 제외 범위

- **버전을 올리거나 릴리즈를 내지 않습니다.** 검사기 동작이 좁아지는 변경이라
  `0.3.0`이 맞다고 보지만, 릴리즈는 따로 승인받고 합니다.
- 아카이브(`.agents/archive/`)와 `history.md`를 비우지 않습니다. `docs/trials/`의
  검증 근거가 거기서 나오고, 앞서 본 저장소들도 자기 기록을 남깁니다.
- 저장소를 새로 파거나 이력을 다시 쓰지 않습니다.
- 005 아카이브 문서의 잘못된 승인 문장은 그대로 둡니다. 사용자가 정했습니다.

## 완료 조건

- README 두 벌에서 루트가 이 저장소의 운영 문서이고 `template/`이 배포물이라는
  것이 읽힌다.
- `lib/check.mjs`에 0.1.x 감지가 남아 있지 않다.
- 0.1.x 감지를 지키던 시험이 함께 빠졌고 `npm test`가 통과한다.
- 아카이브 취급 설명이 README 두 벌에 그대로 남아 있다.
- `cairn check .`, `cairn check template`, `cairn init` 왕복이 모두 통과한다.
- README 두 벌의 구조와 항목이 서로 어긋나지 않는다.

## 전제

- 0.1.x를 쓰는 프로젝트가 있다는 증거가 없어, 없다고 보고 진행한다. 이것은
  확인이 아니라 전제다. 있다면 이 변경 뒤에는 "필수 문서가 없습니다"라는
  메시지만 받고, 무엇이 어디로 갔는지는 안내받지 못한다. 그 대가를 알고 지운다.
- 루트와 `template/`의 혼동은 문구로 푼다. 자기 적용을 그만두는 선택지는
  범위 밖이다 — CI가 `cairn check .`을 돌리고, 이 저장소에서 일하는 에이전트가
  규칙을 읽는 통로이기도 하다.
