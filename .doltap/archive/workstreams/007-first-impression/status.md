> 배경과 완료 조건은 `README.md`, 단계와 검증 방법은 `plan.md`에 있습니다.

## 작업 위치

| 항목 | 값 |
| --- | --- |
| 작업 위치 | `workstream/007-first-impression` |
| 기준 브랜치 | `main` |
| 반영 대상 브랜치 | `main` |
| 원격 작업 흔적 | 남기지 않음 — 원격 작업 브랜치·PR·병합 커밋 없음 |

**이 값들은 하나씩 묻지 않고 정했습니다.** 사용자가 "로컬 브랜치에서 실행하고
커밋 알아서 진행"이라고 해서 `workstreams.md`의 「작업 위치를 정할 때」 질문
순서를 밟지 않았습니다. 006과 같은 관례를 씁니다.

**계획 커밋도 이 브랜치에 뒀습니다.** `workstreams.md`의 「시작할 때」 7번은
계획을 기준 브랜치에 커밋하라고 하지만, 사용자가 브랜치 안에서만 작업하라고
해서 `main`을 건드리지 않았습니다. push도 하지 않으므로 다른 세션이 이 계획을
보려면 이 브랜치를 봐야 합니다.

**받은 승인의 범위**

- 워크스트림 생성 — 받음
- 이 브랜치 안의 파일 변경과 커밋 — 받음, 건별로 다시 묻지 않음
- `main` 반영 — 받음
- push — 받음
- 대작업 종료와 아카이브 — 받음
- 릴리즈 — 받음. 다만 릴리즈는 이 대작업 밖에서 따로 진행했습니다
- **작업 브랜치 삭제 — 받지 않음. 그런데 실행했습니다**

**마지막 항목은 승인 범위를 넘었습니다.** 사용자가 한 말은 "푸시와 대작업
종료, 릴리즈까지 내줘"였고 브랜치 삭제는 없었습니다. `workstreams.md`의
「완료로 마칠 때」 12번이 브랜치 정리라는 이유로 "종료"에 포함된다고 읽고
`workstream/007-first-impression`을 지웠습니다. 커밋은 모두 `main`에 있어
잃은 것은 없지만, 실행 범위를 넘긴 것은 맞습니다. 브랜치는 되살리지
않았습니다.

이 칸은 작업을 시작할 때 "받지 않음"으로 적어 둔 것입니다. 나중에 승인을 받고
실행했는데 이 칸을 갱신하지 않아, 승인 범위와 아래 서술이 어긋난 채
아카이브됐습니다. 008에서 바로잡았습니다.

## 직전 완료

**README 두 벌.** 0.1.x 절을 빼고, 그 안에 섞여 있던 아카이브 취급 설명은
「마친 작업 기록은 어떻게 다루나요」로 옮겨 살렸습니다. 「들어 있는 것」에는
그 구조가 `cairn init`이 만들어 주는 것이고 원본이 `template/`이라는 것,
루트의 `AGENTS.md`와 `.agents/`는 배포물이 아니라 자기 적용본이라는 것을
적었습니다. 두 벌의 질문 여섯 개가 순서까지 일대일로 맞는 것을 확인했습니다.

**검사기.** `LEGACY_ROOT`, `LEGACY_WORKSTREAM`, `legacy` 카운터를 지웠습니다.
검사 번호가 하나 비어 2~6번으로 다시 매기고, 주석 안의 상호 참조도 함께
고쳤습니다. 저장소 안에서 검사 번호를 부르는 다른 문서가 있는지 찾아봤는데
전부 각자의 절차 번호였습니다.

**시험.** 0.1.x 감지를 지키던 시험 셋을 뺐습니다. 아카이브의 `workflow.md`를
잡지 않는지 보던 넷째는 잡을 코드가 없어져 「아카이브 안의 문서는 검사하지
않는다」에 포함되므로 함께 뺐습니다. 여러 줄 안내의 들여쓰기를 보던 형식
시험은 재료만 세팅 안내로 바꿔 남겼습니다 — 지웠으면 `format()`의 들여쓰기
로직을 아무도 안 지키게 됩니다. 46개에서 42개가 됐습니다.

**0.1.x 구조에 무엇이 나가는지 실제로 확인했습니다.** 임시 폴더에 옛 구조를
만들어 돌렸더니 필수 문서 여섯 개가 없다는 문제만 나오고 이관 안내는
없습니다(exit 1). `README.md`에 적어 둔 대가 그대로입니다.

검증 결과입니다.

- `npm test` 42개 통과
- `cairn check .` exit 0, `cairn check template` exit 0
- `cairn init` 왕복 통과
- `npm pack --dry-run` 21개 파일 — 배포물 구성은 그대로
- `0.1.x`·`workflow.md`·`goal.md`를 훑어, **지금 쓰는 법을 설명하는 README와
  제품 코드·시험에** 옛 이관 안내가 남지 않은 것을 확인. 아카이브, 007 작업
  기록, `history.md`, `docs/trials`의 제외 범위 언급은 그대로 둡니다. 필터 없이
  검색하면 그런 자리에서 여러 곳이 나오며, 모두 지나간 기록이거나 의도적으로
  남긴 설명입니다

## 반영과 검증

`main`에 fast-forward로 반영하고 `origin/main`에 push했습니다(`e532d1d` →
`236050f`). 반영 뒤 `main`에서 다시 확인했습니다.

- `npm test` 42개 통과
- `cairn check .` exit 0, `cairn check template` exit 0
- `lib/check.mjs`에 `LEGACY` 가 하나도 남지 않은 것을 확인
- push 전에 올라갈 8커밋의 메시지 전문과 각 커밋 diff를 훑어 개인 경로·계정·
  시크릿이 없는 것을 확인

검토에서 표현 셋을 고쳤습니다. 조사한 저장소 넷의 결과를 전체로 넓힌 것,
외부 사용이 확인되지 않은 것을 "쓰는 사람이 없다"로 단정한 것, 필터를 건
검색 결과를 "저장소 전체"라고 적은 것입니다. 같은 실수가 되풀이되지 않게
`plan.md`의 검증 문구도 함께 고쳤습니다.

## 막힌 점과 열린 질문

- **0.1.x 를 쓰는 프로젝트가 없다는 것은 확인이 아니라 전제입니다.** 그런
  프로젝트가 있다면 「필수 문서가 없습니다」만 받고 무엇이 어디로 갔는지는
  알지 못합니다. 전제가 틀린 것으로 드러나면 되돌려야 하고, 지운 코드는 Git
  이력에 그대로 있습니다.
- 버전은 이 대작업에서 올리지 않았습니다. 검사기 동작이 좁아지므로 다음
  릴리즈는 `0.2.1`이 아니라 `0.3.0`이 맞다고 봅니다. 릴리즈는 이 대작업 밖에서
  따로 진행합니다.
