# 안전한 적용

기존 프로젝트에 cairn을 얹는 절차에서 나온 모순 넷을 없앱니다. 003의 시험에서
발견한 것이고, 넷 다 적용 과정에서만 생깁니다.

## 배경

003에서 임시 기존 프로젝트에 `0.2`를 적용해 보았습니다. 적용 자체는 통과했지만,
그 과정에서 절차 문서끼리 어긋나는 곳이 넷 나왔습니다. 기록만 하고 고치지 않은
채 003을 마쳤습니다.

넷 중 둘은 파일을 만들고 지우는 승인과 얽혀 있어 먼저 처리해야 합니다.

원문은 `.agents/archive/workstreams/003-verify-and-report/findings.md`에
있습니다.

## 이 작업의 범위

- **세팅 중 워크스트림 생성.** 진행 중 기록을 이관하려면 워크스트림을 만들어야
  하는데, 운영 규칙은 허락 없이 만들지 말라고 합니다. 되물을 수 없는 상황에서
  기록을 잃지 않으려면 규칙을 어겨야 합니다.
- **원본 기록을 지울지.** 적용 절차는 사람에게 물으라고 하고, 문서 규칙은 같은
  상태를 두 곳에 두지 말라고 합니다. 묻지 못하면 둘 중 하나는 반드시 어깁니다.
- **골격 위치의 절대 경로.** 적용 절차가 골격 경로를 상태 문서에 적으라고
  했습니다. 그 문서는 부트스트랩 커밋에 들어가므로, 절대 경로를 적으면 공개
  저장소에 운영체제 사용자 이름이 함께 남습니다.
- **골격 폴더 이름 가정.** 검사기가 `.cairn`이라는 이름에만 반응합니다. 골격을
  다른 경로에 두면 적용 뒤 남은 참조를 찾는 검사가 조용히 아무것도 하지
  않습니다.

## 제외 범위

- 검사기의 나머지 정확도 문제는 다루지 않습니다. `current.md` 이름 오탐,
  `~~~` 울타리 오탐, `.agents/` 밖 링크 미탐은 `ideas.md`에 있습니다.
  적용 절차와 얽혀 있지 않아 따로 다루는 편이 낫습니다.
- **검사 범위를 저장소 전체로 넓히지 않습니다.** 오탐이 급격히 늘 수 있습니다.
  적용 절차가 직접 손댄 문서만 보는 방법과 비교한 뒤 정할 문제입니다.
- Windows의 작은따옴표 경로 문제는 이번에 다루지 않습니다.
- 릴리즈(`v0.2.0` 태그와 GitHub Release)는 만들지 않습니다.
- `0.1.x` 실이관, 원격 PR 흐름, 영어 템플릿, npm 등록도 이번이 아닙니다.

## 완료 조건

- `APPLY.md` 3번의 변경 승인을 받은 뒤에는 **네 모순 때문에 추가적인 적용 방향을
  결정하지 않는다.** 각각에 대해 무엇을 하면 되는지가 문서에 적혀 있다.

  질문이 아예 없다는 뜻은 아닙니다. 문서에 남길 수 없는 임시 경로처럼, 값을
  받아야만 진행할 수 있는 것은 다시 물을 수 있습니다. 없애려는 것은 **무엇을
  할지 정하지 못해 막히는 자리**입니다.

  커밋, 반영, 아카이브처럼 기존 규칙이 원래 요구하는 실행 승인은 그대로
  받습니다. 변경안을 보여주고 답을 받는 왕복은 되물을 수 없는 실행에서
  불가능하고, 문서로 없앨 수 있는 것도 아닙니다. 이 대작업이 없애려는 것은
  변경 승인을 받은 **뒤에 네 모순 때문에 방향을 다시 정해야 하는 자리**입니다.
- 공개 저장소에 적용해도 절차를 그대로 따르는 것만으로 사용자 이름이 새지
  않는다. **추적되는 파일에 처음부터 적지 않는 것으로 확인합니다.** 나중에
  지우는 것은 부트스트랩 커밋에 이미 들어간 값을 없애지 못합니다.
- 골격이 `.cairn`이 아닌 경로에 있어도, 적용 뒤 남은 참조를 확인할 방법이
  있거나 검사기가 무엇을 못 보는지 문서에 밝혀져 있다.
- 고친 절차로 적용을 한 번 더 돌려 네 모순이 실제로 사라졌는지 확인했다.
- `npm test`, `check template`, `check .`가 통과한다. 검사기를 고쳤으면 잡아야
  할 경우와 잡으면 안 되는 경우가 시험으로 고정되어 있다.

## 전제

- 003의 시험 조건과 같습니다. 판정 근거는 항목마다 구분해서 밝힙니다 — 파일
  상태, 명령 출력, 실제 도구 호출 기록을 우선하고, 자기 보고에 기댄 항목은 그
  사실을 적습니다.
- 처음 작업한 세션에서는 Codex 실적용을 할 수 없었습니다. 이후 별도 Codex
  세션에서 결과를 전달받아 검증했습니다. 종료 검사는 원격 `npx` 실행이 차단돼
  같은 cairn 작업 트리의 로컬 검사기로 대체했습니다.
