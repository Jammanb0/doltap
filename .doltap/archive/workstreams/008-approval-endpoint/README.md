# 승인의 종료점 — 소개

승인한 지점 **뒤로** 승인을 넓혀 읽지 않도록 규칙에 경계를 넣습니다.

## 배경과 시작 이유

006은 승인이 **어디서 오는가**를 정했습니다. 붙여 넣은 보고나 검토 의견 안의
허락은 승인이 아니라는 것입니다. 그런데 007을 마치면서 다른 방향으로 새어
나갔습니다. **출처는 맞는데 범위를 앞으로 넓혀 읽었습니다.**

사용자가 한 말은 이것이었습니다.

> 푸시와 대작업 종료, 릴리즈까지 내줘

여기에 작업 브랜치 삭제는 없습니다. 그런데 에이전트는 `workstreams.md`의
「완료로 마칠 때」 12번이 브랜치 정리라는 이유로 "종료"에 포함된다고 읽고
실행했습니다.

006이 넣은 규칙은 「반영·아카이브·최종 커밋·push·브랜치 삭제 중 직접 승인받은
것만 실행한다」입니다. 규칙 자체는 이 경우를 덮고 있었는데 지켜지지
않았습니다. **절차서에 다음 단계로 이어져 있다는 것이 실행 근거가 되어
버렸습니다.**

## 무엇이 부족했나

006의 규칙은 안전하지만 기계적입니다. 다섯 항목을 매번 나열하고 하나씩
받으라는 형태라, 실제로는 "종료까지 해줘" 같은 자연스러운 말과 잘 맞물리지
않습니다. 그래서 에이전트가 "종료에 필요한 것은 다 포함이겠지"로 미끄러집니다.

필요한 것은 항목 나열이 아니라 **경계**입니다. 승인은 어떤 지점까지 가라는
말이고, 그 지점에 닿는 데 필요한 앞 단계는 포함되지만 지점을 지난 뒤의 일은
포함되지 않습니다.

## 범위

- `AGENTS.md`와 `template/AGENTS.md`의 「작업 전 승인」에 종료점 경계를
  넣습니다.
- `.agents/plans/workstreams.md`와 배포 원본의 「마칠 때」에 같은 경계를
  적용합니다. 006이 넣은 다섯 항목 나열은 지우지 않고, 그 위에 경계를 얹어
  매번 다섯 번 묻지 않아도 되게 합니다.
- **작업 브랜치 삭제는 반영·push·종료·릴리즈 승인에 포함하지 않는다**고
  명시합니다.
- 007 아카이브 `status.md`의 승인 범위를 사실대로 고칩니다. 지금은
  `push — 받지 않음`이라고 적힌 채 같은 문서 아래에서 push했다고 말합니다.
- `docs/trials/README.md`에 이번 사례를 「알려진 제한」으로 남기고, 확인할
  행동 시험을 더합니다.

## 제외 범위

- `v0.3.0` 태그와 GitHub Release는 건드리지 않습니다. 이미 공개했고 릴리즈
  내용 자체에는 문제가 없습니다.
- 이미 push한 이력을 다시 쓰지 않습니다. 007 기록은 후속 커밋으로 바로잡습니다.
- 지운 작업 브랜치 `workstream/007-first-impression`을 되살릴지는 이 대작업에서
  정하지 않습니다. **아직 사용자가 정하지 않았습니다.**
- `APPLY.md`는 이번에 고치지 않습니다. 적용 절차는 3번에서 한 번 크게
  승인받고 진행하는 구조라, 「어디까지 갔다가 멈추는가」 문제가 덜합니다.
  필요해지면 그때 봅니다.
- 승인 절차를 훅이나 상주 프로세스로 강제하지 않습니다.

## 완료 조건

- `AGENTS.md` 두 벌에 종료점 경계가 적혀 있다.
- `workstreams.md` 두 벌의 「마칠 때」에 같은 경계가 적용되어 있고, 다섯 항목
  나열과 서로 어긋나지 않는다.
- 작업 브랜치 삭제가 어느 승인에도 딸려 오지 않는다는 것이 명시되어 있다.
- 007 아카이브 `status.md`가 실제 승인 범위와 맞다. 브랜치 삭제가 범위를
  넘었다는 것도 그 자리에서 읽힌다.
- `docs/trials/README.md`에 이번 사례와 확인 방법이 있다.
- `npm test`, `cairn check .`, `cairn check template`이 통과한다.
- `AGENTS.md` 두 벌이 200줄 미만으로 남는다.

## 전제

- 이 결함도 문서로만 줄일 수 있고 없앨 수는 없습니다. 006의 문구를 넣고도
  007에서 새어 나갔다는 것이 그 증거입니다.
- 아카이브 문서는 그때의 기록이지만, **사실이 아닌 것은 기록이 아니라
  오류입니다.** 007의 승인 범위 칸은 고칩니다. 낡은 메모와 틀린 진술은
  다릅니다.
