# CI 시험 안정화

잠금 시험이 실행 환경의 우연한 PID 존재 여부에 따라 실패하지 않도록 고칩니다.

## 배경

v0.4.1의 CI 실행 34817927152에서 Ubuntu / Node 22만 실패했습니다.
`test/ids.test.mjs`의 오래된 잠금 시험이 PID 1234의 주인이 없다고 가정하지만,
구현은 살아 있는 주인의 잠금을 보호합니다. 010 종료 실행 34764974816에서도
같은 시험이 실패했습니다. 나머지 다섯 환경의 통과와 원인을 구분합니다.

## 범위

- 실제 PID 존재 여부에 의존한 실패를 재현하고 시험 입력을 고정합니다.
- 같은 시험 파일의 고정 PID 가정을 점검하고 생존·종료·권한 오류를 구분합니다.
- 전체 시험과 문서 검사, 파일별 시험 보고서를 확인합니다.
- 로컬 재현·검증과 아직 실행하지 않은 원격 CI 결과를 구분해 기록합니다.

제품의 잠금 정책, 새 의존성, CI 행렬 변경은 포함하지 않습니다.
초기 작업은 로컬 검증까지였으며, 후속 승인에 따라 main 반영·푸시·원격 CI 확인과
대작업 종료·아카이브·작업 브랜치 삭제까지 진행합니다. 배포물 변경이 없으면
새 릴리즈는 만들지 않습니다.

## 검증 조건

1. 수정 전 실패한 PID 생존 조건에서 수정 후 해당 시험이 통과합니다.
2. 살아 있는 잠금 보호와 죽은 주인의 오래된 잠금 회수가 함께 검증됩니다.
3. 전체 시험, check template, check ., 시험 보고서 일치 검사가 통과합니다.
4. 원격 실행이 없으면 CI 해결 완료로 표현하지 않고 검토 대기로 남깁니다.
