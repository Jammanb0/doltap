# cairn 구조 적용 — 진행

> 배경과 완료 조건은 `README.md`에 있습니다. 여기는 지금 어디까지 왔고 다음이
> 무엇인지만 다룹니다.

이 프로젝트에는 아직 cairn의 워크스트림 규칙이 자리 잡지 않았습니다. 그래서 이
대작업만은 일반 규칙 대신 아래 단계를 따릅니다. 적용이 끝나 이 워크스트림을
아카이브한 뒤부터는 `.agents/plans/README.md`와 루트 `workflow.md`가 원본입니다.

## 현재 상태

**완료했습니다.** 1~7단계를 모두 밟았고 완료 조건을 하나씩 대조했습니다.
8단계(`.cairn/` 정리)는 자기 적용이라 해당 없음입니다.

적용 과정에서 나온 발견은 `README.md`의 「자기 적용에서 나온 것」에 있습니다.
검사기 오탐과 골격 서식은 대작업으로 만들 크기가 아니라, 이 워크스트림을 닫고
`main`에서 바로 고칩니다.

**이 적용은 자기 적용입니다.** 아래 단계에 나오는 `.cairn/` 경로는 이 저장소의
`template/`, `setup-workstream/`, `APPLY.md`로 읽습니다. 8단계(`.cairn/` 정리)는
해당 없음입니다.

## 다음 단계

### 1. 규칙을 가른다

기존 지시 파일에 아래 성격의 내용이 섞여 있으면 해당 파일로 옮깁니다.

- 완료 전 확인 방법, 테스트·빌드 명령 → `.agents/rules/verification.md`
- 답변 방식, 설명 태도 → `.agents/rules/communication.md`
- 목적, 배경, 장기 방향, 범위의 상세 설명 → `.agents/plans/goal.md`

**항상 지켜야 하는 제약은 `AGENTS.md`에 남깁니다.** 옮기는 것은 상세 설명이지
제약 자체가 아닙니다. 특히 「하지 않는 것」은 작업 중에 매번 걸리는 선이라
`AGENTS.md`에 짧게 남기고, 그렇게 정한 배경만 `goal.md`로 옮깁니다.

| 성격 | 어디에 |
| --- | --- |
| 작업할 때마다 걸리는 제약, 금지 사항, 승인 규칙 | `AGENTS.md`에 짧게 |
| 그 제약을 왜 정했는지, 배경과 장기 방향 | `.agents/plans/goal.md` |
| 특정 작업을 할 때만 필요한 절차와 체크리스트 | 해당 문서에 두고 `AGENTS.md` 안내표에서 가리킴 |

기존 `.agents/`가 cairn과 다른 구조라면 폴더를 지우지 말고 위 기준으로 내용만
옮깁니다. 어디에 넣을지 애매한 것은 사용자에게 묻습니다.

### 2. 기록을 옮긴다

기존에 진행 기록을 담은 문서(`TODO.md`, `NOTES.md`, 핸드오프 문서 등)가 있으면
성격에 따라 나눠 옮깁니다. 루트 `workflow.md`는 시작점이고 `history.md`는 짧은
색인이라, 상세 내용을 여기에 쌓지 않습니다.

| 무엇 | 어디로 |
| --- | --- |
| 진행 중인 작업의 상세 기록 | `.agents/plans/workstreams/<번호>-<이름>/workflow.md` |
| 그 작업의 배경·범위·완료 조건 | 같은 폴더의 `README.md` |
| 진행 중인 작업이 어디 있는지 가리키는 줄 | 루트 `.agents/plans/workflow.md` |
| 이미 끝난 작업의 상세 기록 | `.agents/archive/workstreams/<번호>-<이름>/` |
| 끝난 작업의 한 줄 요약과 보관 위치 | `.agents/plans/history.md` |
| 아직 착수를 약속하지 않은 것 | `.agents/plans/ideas.md` |

여기서 새로 만드는 워크스트림의 번호는 이 세팅 다음 번호부터 씁니다. 원본 문서를
지울지는 사람에게 묻습니다.

### 3. 연결한다

**이 단계를 빠뜨리면 파일만 생기고 아무도 읽지 않습니다.**

- `AGENTS.md`에 문서 안내표를 넣습니다. 기존 안내가 있으면 항목을 더합니다.
- `CLAUDE.md`가 없으면 `@AGENTS.md` 한 줄로 만듭니다. 본문이 직접 들어 있으면
  그 내용을 `AGENTS.md`로 옮기고 한 줄로 줄일지 사람에게 묻습니다.
- `.agents/` 커밋 여부는 세팅을 시작할 때 정했습니다. 커밋하지 않기로 했으면
  `.gitignore`에 들어가 있는지 확인합니다.

### 4. 현재 상태를 채운다

`goal.md`와 루트 `workflow.md`를 빈 틀로 두지 않습니다. README, 코드, `git log`,
열린 이슈에서 확인되는 것으로 채웁니다. 확인되지 않는 것은
`<!-- 확인 필요: 무엇을 -->`로 남기고 사람에게 무엇이 비었는지 알립니다.

### 5. 어긋나는 규칙을 처리한다

기존 규칙과 골격이 충돌하면 조용히 덮어쓰지 않습니다. 무엇과 무엇이 어긋나는지
짚고 어느 쪽을 따를지 사람에게 묻습니다. 흔한 경우는 이렇습니다.

- 커밋 메시지 언어와 형식 — 기존 `git log`를 따르는 것이 보통 맞습니다
- 승인 범위 — 팀마다 다릅니다
- 이미 다른 문서 체계를 쓰고 있는 경우 — 섞을지 한쪽으로 통일할지 정해야 합니다

정한 결과와 그 이유는 이 문서 아래 「결정」에 남깁니다.

### 6. 새 규칙을 다시 읽는다

**적용으로 바뀐 `AGENTS.md`와 `.agents/rules/`의 문서를 전부 다시 읽습니다.**
지금 세션이 파일 변경을 자동으로 다시 읽는다고 가정하지 않습니다. 이 단계부터는
방금 놓은 규칙이 적용됩니다.

### 7. 적용됐는지 확인한다

파일이 생긴 것만으로는 확인이 되지 않습니다.

**명령으로 확인**

```bash
node .cairn/bin/cairn.mjs check
```

안내표가 가리키는 경로가 실재하는지, `CLAUDE.md`가 `AGENTS.md`로 이어지는지,
남은 채우기 자리와 워크스트림 상태가 어떤지를 한 번에 봅니다. 문제가 있으면
종료 코드 1로 끝납니다. 아래 항목 가운데 기계가 대신 볼 수 없는 것은 직접
확인합니다.

**문서로 확인**

- `grep -rn "채우기\|고르기\|확인 필요" AGENTS.md .agents/` 결과에 남은 것이
  무엇인지 사람에게 알렸는가
- `CLAUDE.md`에서 `AGENTS.md`로, `AGENTS.md`의 안내표에서 `.agents/`의 각
  파일로 실제로 이어지는가. 안내표에 적힌 경로가 실재하는가
- 적용 전에 있던 규칙 중 사라진 것이 없는가. 옮겼다면 옮긴 자리에 실제로 있는가
- 같은 규칙이 두 곳에 원본으로 중복되어 있지 않은가
- 앞으로 계속 쓰는 활성 문서에 `.cairn` 참조가 남아 있지 않은가. 곧 지울 폴더를
  가리키면 안 됩니다. **이 세팅 워크스트림 문서와 그 아카이브 기록은 검사에서
  뺍니다.** 적용 절차를 설명하느라 `.cairn` 경로를 담고 있는 것이 정상입니다.

  ```bash
  grep -rn --exclude-dir='*-cairn-setup' \
    "\.cairn" AGENTS.md CLAUDE.md .agents/
  ```

**실제로 확인**

- 새 세션에서 "지금 뭐 하던 중이었지?"라고 물었을 때 에이전트가
  `.agents/plans/workflow.md`를 찾아 읽고 답하는가

### 8. `.cairn/`을 정리한다

이 단계는 세팅에만 있습니다. 지우기 전에 확인합니다.

- 7번의 `.cairn` 참조 검사가 통과했는가
- `.cairn/` 안의 파일을 사용자가 고친 것이 없는가

```bash
git -C .cairn status --short
```

**이 명령이 승인 거부나 오류로 실패하면 확인되지 않은 것입니다.** 내가 이
폴더를 편집하지 않았다는 것은 사용자가 편집하지 않았다는 증거가 아닙니다.
확인될 때까지 지우지 말고, 무엇을 확인하지 못했는지 사람에게 알립니다.

확인이 끝나면 폴더를 지웁니다.

```bash
rm -rf .cairn
```

`.gitignore`에서는 **이번 적용에서 추가한 `.cairn/` 줄만** 지웁니다. 원래 있던
항목은 건드리지 않습니다.

### 9. 일반 흐름으로 마무리한다

6번에서 새 규칙을 다시 읽었으므로 여기서부터는 일반 규칙이 적용됩니다. 다만
일반 흐름에는 최종 커밋이 들어 있으니, **세팅에만 해당하는 정리를 먼저 끝낸 뒤에
들어갑니다.** 순서가 뒤바뀌면 정리 내용이 커밋에서 빠집니다.

1. `.cairn/APPLY.md` 5단계에서 기존 지시 파일에 넣었던 임시 연결 문구를 위
   3번의 정식 안내표로 대체합니다.
2. 루트 `workflow.md`의 「현재 대작업」에서 이 세팅을 뺄 때, 2번에서 옮긴
   기록으로 만든 다른 워크스트림이 있으면 그것은 남긴다는 것을 확인합니다.
3. `README.md`의 완료 조건을 하나씩 대조합니다.
4. **루트 `.agents/plans/workflow.md`의 「대작업 관리 흐름」 마지막 단계와
   「대작업을 반영할 때」를 그대로 따릅니다.** 이력 기록, 아카이브 이동, 최종
   커밋, 반영, 확인, 브랜치 정리가 거기 있습니다. 같은 절차를 여기에 다시 적지
   않습니다.

## 결정

골격 기본값과 어긋나는 기존 규칙은 없었습니다. 시작하며 정한 것만 적습니다.

- 커밋 메시지는 기존 `git log`를 따라 한국어 `type(scope): ~한다` 형식을 쓴다.
- `.agents/`는 커밋한다. 공개 저장소이고 자기 운영 기록을 보이는 것이 목적이다.
- `docs/trials/README.md`는 지금 자리에 두고 `AGENTS.md` 안내표에서 가리킨다.
  공개 문서 성격이라 `.agents/` 안으로 넣지 않는다.
- 「하지 않는 것」에는 훅으로 절차를 강제하지 않는다는 한 줄만 넣고, 형식 변환과
  자동 갱신은 바뀔 수 있는 판단이므로 `goal.md`의 범위에 적는다.

## 열린 항목

- `APPLY.md`와 `setup-workstream/` 문서에 자기 적용 경로를 넣을지. 이 대작업을
  마친 뒤 별도 변경으로 판단합니다.
