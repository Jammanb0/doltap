# 대작업: cairn 구조 적용

이미 작업 중인 이 프로젝트에 cairn의 문서 골격을 얹는 대작업입니다. 기존 규칙과
진행 기록을 살리면서 옮겨 담고, 서로 이어지게 연결합니다.

## 배경

이 저장소는 cairn을 만들어 배포하는 곳이지만, 정작 cairn 구조를 자기 자신에게
적용한 적이 없었습니다. 루트에 `AGENTS.md`도 `CLAUDE.md`도 `.agents/`도 없어
새 세션마다 무엇을 하던 중인지 다시 설명해야 했고, 커밋 관례나 승인 범위 같은
규칙도 `git log`와 그때그때의 대화에만 있었습니다.

적용 자체가 목적이 아닙니다. 적용 절차와 `cairn check`, 워크스트림 수명 주기를
실제로 한 번 굴려 보는 것이 이 대작업의 목적입니다.

## 이 작업의 범위

- 기존 지시 파일과 기록 문서를 cairn 구조의 제자리로 옮깁니다.
- 기존 규칙을 덮어쓰거나 임의로 버리지 않습니다. 어긋나는 항목은 사용자가
  정합니다.
- 문서가 서로 이어지게 연결합니다. 파일만 생기고 아무도 읽지 않는 상태를
  만들지 않습니다.
- 코드는 건드리지 않습니다. 이 대작업은 문서와 운영 기록만 다룹니다.

## 완료 조건

- `CLAUDE.md` → `AGENTS.md` → 안내표 → `.agents/`의 각 문서로 실제로 이어진다.
- 적용 전에 있던 규칙 중 사라진 것이 없다. 옮긴 것은 옮긴 자리에 있다.
- 같은 규칙이 두 곳에 원본으로 중복되어 있지 않다.
- `goal.md`와 루트 `workflow.md`가 빈 틀이 아니다. 확인되지 않는 것은
  `확인 필요`로 표시되어 있다.
- 새 세션이 `.agents/plans/workflow.md`를 스스로 찾아 읽고 진행 상황을 답한다.
- `.cairn/`이 정리되었고, 앞으로 계속 쓰는 활성 문서에 `.cairn` 참조가 남아 있지
  않다. 이 세팅 워크스트림 문서와 그 아카이브 기록은 예외다 — 적용 절차를
  설명하느라 `.cairn` 경로를 담고 있는 것이 정상이다.

이 프로젝트에만 해당하는 조건입니다.

- `node bin/cairn.mjs check .` 가 문제 0으로 통과한다.
- `.cairn/` 정리는 **해당 없음**이다. 자기 적용이라 클론하지 않았고, 골격은
  이 저장소의 `template/`과 `setup-workstream/`에서 바로 가져왔다.
- 적용 과정에서 나온 발견을 아래 「자기 적용에서 나온 것」에 남긴다.

## 조사 결과

| 항목 | 확인한 것 |
| --- | --- |
| 지시 파일 | `AGENTS.md`, `CLAUDE.md`, `.agents/`, `.cursorrules`, `.claude/` 모두 없음 |
| 진행 기록 | `docs/trials/README.md` (시험 기록) 하나 |
| 기준 브랜치 | `main`, upstream `origin/main`, 원격 기본 브랜치도 `main` |
| 저장소 공개 여부 | 공개 |
| `.agents/` 커밋 | 커밋한다. 공개 저장소이고 자기 운영 기록을 보이는 것이 목적 |
| 커밋 관례 | 한국어 `type(scope): ~한다`. 최근 커밋 전부 일치 |
| 런타임 | Node 18 이상, ESM, 의존성 없음, `npm test` |
| 그 밖 | 로컬 전용 브랜치 `backup-before-rewrite` 가 있으나 이 작업과 무관해 손대지 않음 |

**옮길 규칙 파일이 없습니다.** 일반적인 적용은 흩어진 규칙을 옮겨 담는 일이지만,
여기서는 문서로 존재한 적 없는 규칙을 명문화하는 일이 됩니다.

## 자기 적용에서 나온 것

- `APPLY.md`는 `.cairn/`을 클론한 상태를 전제합니다. 자기 적용에는 그 폴더가
  없고 `template/`, `setup-workstream/`이 저장소 안에 있으므로, 절차의
  `.cairn/` 경로를 그대로 읽을 수 없습니다.
- `APPLY.md` 5번의 임시 연결 문구가 필요 없습니다. 기존 진입점이 없어 새로
  만드는 `AGENTS.md`의 안내표가 처음부터 `.agents/`를 가리키기 때문입니다.
- `cairn check`가 「채우기」·「고르기」·「확인 필요」를 낱말로 셉니다. 절차를
  설명하느라 그 말이 들어간 문장까지 잡습니다. 실제 자리는 `<!-- 채우기: -->`
  주석 형태이므로 그것만 세도록 고쳐야 합니다.
- `template/AGENTS.md`에서 「하지 않는 것」의 채우기 주석과 다음 제목 사이에 빈
  줄이 없습니다. 채우면 제목이 앞 문장에 붙습니다.
- 아직 고치지 않은 결함을 둘 자리가 구조에 없습니다. `ideas.md`는 현재 문제를
  두지 않는 곳이고 루트 `workflow.md`는 대작업만 적습니다. 대작업으로 만들 만큼
  크지 않은 결함은 아카이브로 함께 묻힙니다. 이번에는 곧바로 고치므로 문제가
  되지 않았습니다.
- 아카이브로 옮긴 문서까지 채우기 자리로 셉니다. 지나간 기록이라 채울 일이
  없으므로 그 검사에서는 빼는 것이 맞아 보입니다. 연결 검사는 계속할지 함께
  정합니다.
- 「새 세션이 스스로 찾아 답하는가」는 실제로 새 세션에서 확인했습니다. 진행 중인
  대작업, 작업 브랜치, 지금 선 단계까지 정확히 답했습니다.
