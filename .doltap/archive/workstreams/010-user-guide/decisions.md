# 처음 쓰는 사람을 위한 안내 — 결정

## 사용자 요청대로 계획도 로컬 작업 브랜치에 둔다

- `이번만` 010의 작업 위치와 승인 범위

사용자가 009 종료 뒤 새 로컬 브랜치에서 작업하도록 지정했습니다. 계획 커밋도
이 브랜치에 뒀고 진행 중에는 이 브랜치에서 이어받도록 했습니다. 종료 승인 뒤
main으로 반영했습니다. 009 작업 브랜치는 그대로 보존합니다.


## 처음 읽는 순서와 명령 참고를 나눈다

- `계속 유효` 활성 원본: guide/README.md

개념과 대작업 흐름을 먼저 읽고 시작·일상·연결·이동·검토·종료로 찾아가게 합니다.
GRAPH.md는 guide/reference.md와 hooks.md로 내용을 옮겼습니다. 상세 설명은
참고 문서에 두고 처음 읽는 글에는 목적과 최소 실행 순서를 설명합니다.
대작업 생성·진행 판단·종료는 사람과 에이전트가 맡고 CLI가 자동 수행하지 않는다는
점을 guide/workstreams.md에 별도로 적습니다.

## 관찰한 Windows 잠금 열기 오류는 배타적 생성만 제한적으로 재시도한다

- `계속 유효` 활성 원본: docs/document-graph-spec.md 「관리 범위와 발급」

009 원격 CI의 Windows / Node 24에서 잠금 open EPERM이 관찰됐습니다.
운영체제 내부 원인이나 이전 무상세 실패와의 동일성은 확정하지 않습니다.
다른 주인의 파일을 지우지 않고 제한된 재시도 뒤에도 실패하면 원래 오류를
반환합니다. 로컬 오류 주입·동시 발급 반복을 검증했고, 종료 승인 뒤 원격 6개
환경의 통과를 확인했습니다. 실행 근거는 docs/trials/ci-009.md에 있습니다.

## 환경 조사 결과로 적용 절차의 대상과 조건을 정한다

- `계속 유효` 활성 원본: APPLY.md, guide/adoption-layouts.md, template/AGENTS.md와 template/.doltap/plans/workstreams.md

운영 루트·작업 저장소·골격 위치·에이전트 시작 위치를 같은 것으로 가정하지 않습니다.
적용·해당 없음·미확인을 나눠 승인된 계획으로 만들며 새 설치 프로그램은 추가하지
않습니다. 조건은 세팅 문서에 기록하고 이후에도 필요한 것은 활성 운영 문서에
남깁니다. Git 없는 기록, 별도 개인 Git, 읽기 전용 회사 지침을 구분합니다.
CLI 구조 검사로 호스트 권한·프로젝트 설정·지침 준수를 검증했다고 하지 않습니다.
