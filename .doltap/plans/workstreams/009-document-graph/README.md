# 문서 그래프 기반

[완료 조건으로 이동](README.md#doltap-s-7qpp5x4m-start)

문서 사이의 의미 관계를 사람이 읽는 마크다운에 명시하고, 검사기가 그 관계를
기계적으로 확인하고 탐색하게 만듭니다. 공개 이름을 바꾸는 것에서 시작해 운영
폴더, ID·관계 문법, 검사기, 기존 기록 이관까지 한 덩어리로 옮깁니다.

설계의 원본은 `docs/document-graph-design.md`입니다. 이 문서는 그 내용을 옮겨
적지 않고, 무엇을 왜 이 대작업으로 묶었는지와 어디까지 가야 끝인지만 정합니다.

## 배경

009 시작 당시 문서 사이의 실제 관계는 대부분 에이전트가 글을 읽고 기억해서 복원합니다.
당시 `cairn check`가 보던 것은 백틱으로 감싼 경로가 실재하는지까지이고, 어느 규칙이
어느 결정과 검증에 근거하는지는 보지 않았습니다.

문서가 적을 때는 그래도 굴러갑니다. 문제는 아카이브가 쌓일 때입니다. 007을
아카이브한 뒤에 실제로 한 번 새어 나갔습니다. 그 워크스트림의 `status.md`에
「외부 사용이 확인되지 않았음」을 「쓰는 사람이 없음」으로 단정한 표현을 고쳤다는
검토 기록이 남아 있었는데, 나중의 검토가 `history.md`의 한 줄과 활성 `ideas.md`
만 읽고 그 파일을 열지 않아 이미 고친 단정을 다시 썼습니다.

읽은 것을 잊은 게 아니라 **읽어야 할 범위를 애초에 고르지 못한 것**입니다.
당시 검사기는 아카이브를 탐색에서 빼므로 이 누락을 드러내지 못했습니다. 관계를
문서에 명시하고 기계가 따라갈 수 있게 만드는 것이 이 대작업의 목적입니다.

## 이 작업의 범위

`docs/document-graph-design.md`의 「한 대작업에서 함께 끝낼 기반」이 범위의
원본입니다. 항목을 여기 옮겨 적으면 두 곳이 갈라지므로, 묶음 단위로만 적습니다.

```text
이름     공개 이름 · npm 패키지명 · CLI · 운영 폴더 · 앵커 접두사
형식     document·section·block ID · start/end 범위 · 표준 링크와 관계 문법
검사기   무상태 검사 · 도달성 · 이동 복구 · 삭제 안전성 · JSON 출력과 종료 코드
상태     contentHash · graphHash · 대상별 최신 검토 기록
조회     지도 · 맥락 조회 · 범위 감사
이관     이 저장소 · template · setup-workstream · APPLY · README 두 벌 · 레거시
전환     NOTICE 요약 → 엄격 검사 → 기본값 승격
```

이 일곱 묶음은 서로의 형식에 영향을 주므로 나누지 않습니다. 특히 이름은 운영
폴더와 앵커 접두사를 통해 모든 문서와 ID에 박히므로, 이름을 미루면 나머지를
두 번 하게 됩니다.

`ideas.md`와 `docs/trials/README.md`에 남은 항목 중 같은 코드를 다시 건드리는
것들도 여기서 함께 처리합니다. 어느 항목이 흡수되고 어느 항목이 밖에 남는지는
설계 기록의 「현재 기록된 다른 할 일과의 선후관계」에 있습니다.

## 제외 범위

- **기반 형식을 소비하는 기능은 뒤로 미룹니다.** 대화형 그래프 화면, 편집기
  연동, 다른 도구용 내보내기, 군집화, 범위를 정하지 않은 AI 관계 추천, 대규모
  저장소용 성능 최적화가 여기 해당합니다. 이것들은 ID·관계 형식을 바꾸지 않고
  나중에 얹을 수 있습니다.
- **템플릿 영어판과 npm 레지스트리 등록은 이 대작업 뒤로 미룹니다.** 지금
  하면 폴더·문법·CLI가 바뀐 뒤 다시 해야 합니다.
- **구형 구조를 영구 지원하는 호환 계층을 만들지 않습니다.** 다만 구형
  구조를 발견했을 때 무엇이 바뀌었고 이관 안내가 어디 있는지 알리는 것은
  범위 안입니다.
- **doltap이 AI API를 직접 호출하게 만들지 않습니다.** 의미 판단은 이미 쓰고
  있는 호스트 에이전트가 맡습니다.
- 하지 않기로 한 것의 원본은 설계 기록의 「하지 않을 것」입니다.

## 완료 조건

설계 기록의 「009 워크스트림의 완료 조건」을 **그대로 이 대작업의 완료 조건으로
확정합니다.** 종료 판단은 그 목록과 아래 항목으로 합니다.

문구를 여기 옮겨 적지 않고 그 절을 가리킵니다. 원본이 둘이 되면 갈라지기
때문입니다. 그래서 **그 절을 고치는 것은 이 대작업의 완료 조건을 바꾸는 일**이
됩니다. 고쳐야 할 이유가 생기면 `decisions.md`에 무엇을 왜 바꿨는지 남깁니다.

아래는 그 목록에 더해 이 대작업이 스스로 만족해야 하는 조건입니다.

- 새 공개 이름이 정해지고, 옛 이름 `cairn`이 npm 패키지명·CLI·운영 폴더·앵커
  접두사에 남아 있지 않다. 역사와 출처를 설명하는 문장은 예외다.
- 설계 기록의 「구현 전에 확정하거나 시험할 것」 27개가 각각
  확정·시험 완료·범위 밖 중 하나로 처리되고, 그 결과가 `design.md`와
  `decisions.md`에 남는다. **형식이 미확정인 채로 구현에 들어간 항목이 없다.**
  실제로 띄워 봐야 아는 확인은 형식과 구분한다 — 그런 항목은 어느 단계에서 닫을지
  `plan.md`의 그 단계 검증에 적고, 거기서 닫히지 않으면 그 단계가 끝나지 않는다.
- 잡아야 할 경우와 잡으면 안 되는 경우가 모두 시험으로 고정된다. 오탐을 내는
  검사는 아무도 보지 않게 된다.
- 007의 누락 사례가 회귀 시험으로 남는다. 활성 판단이 의존하는 아카이브 전제를
  맥락 조회가 실제로 찾아낸다.
- `npm test`와 검사기의 `check template`·`check .`가 모두 통과하고, 새 이름의
  `init`으로 만든 빈 프로젝트가 곧바로 검사를 통과한다.
- 저장소 전체에서 옛 경로와 문법을 현재 사용법으로 안내하는 곳이 없다.
  README 두 벌, `APPLY.md`, `template/`, `setup-workstream/`, 시험까지 본다.
- 이 대작업에서 확인한 사실이 설계 기록과 다르면 `docs/document-graph-design.md`
  의 상태 표기와 해당 절을 함께 갱신한다.

- `derived-from` [document-graph-design.md](../../../../docs/document-graph-design.md#doltap-d-knwnrg0q-start)

## 전제

이 프로젝트에 계속 적용되는 전제는 `.doltap/plans/decisions.md`에서 관리합니다.
- 이 저장소는 자기 자신에게 골격을 적용해 운영하므로, 규격 변경과 자기 이관이
  같은 대작업 안에서 함께 움직입니다. 배포하는 골격 원본은 `template/`입니다.
- 새 이름이 정해지기 전에는 불변 ID를 발급하지 않습니다. 가칭 접두사로 먼저
  발급하면 이름을 바꾼 뒤 ID를 다시 손대야 합니다.
- 가장 어려운 단일 항목은 해시 계산이 아니라 **무엇을 의미 내용으로 볼지 정하는
  정규화 규칙**입니다. 잘못 정하면 서식만 바꿔도 재검토가 쏟아지거나 중요한
  변경을 놓칩니다.
