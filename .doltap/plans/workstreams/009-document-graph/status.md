# 문서 그래프 기반 — 상태

> 배경과 완료 조건은 `README.md`, 단계와 검증 방법은 `plan.md`, 정한 것과 그
> 이유는 `decisions.md`에 있습니다. 여기는 지금 어디까지 왔고 다음이 무엇인지만
> 다룹니다.

## 작업 위치

| 항목 | 값 | 어떻게 정했나 |
| --- | --- | --- |
| 작업 위치 | `workstream/009-document-graph` | 사용자 지시 — "로컬 브랜치 하나 만들어서 진행하고" |
| 기준 브랜치 | `main` | 실제 작업 시작점 — 갈림점이 `main`의 `50cf939` |
| 반영 대상 브랜치 | `main` | 사용자가 이 대화에서 직접 확인 |
| 원격 작업 흔적 | 남기지 않음 — 원격 작업 브랜치·PR·병합 커밋 없음 | 사용자 지시 — "푸시는 진행하지 말아줘" |

기준 브랜치는 사용자가 따로 고른 값이라고 적지 않고, 실제로 이 작업 브랜치를
만든 시작점을 기록합니다. 작업 위치는 처음 요청에서, 반영 대상은 뒤에 사용자가
직접 정했습니다.

**원격 작업 흔적은 push 금지 지시에서 나온 값입니다.** 원격에 작업 브랜치를
만들고 PR을 열지는 따로 묻지 않았습니다. 나중에 push를 승인받으면 그때 다시
정합니다.

계획 커밋도 기준 브랜치가 아니라 이 브랜치에 둡니다. 그 이유와 대가는
`decisions.md`에 있습니다.

**받은 승인의 범위**

- 워크스트림 생성 — 받음 ("다음 대작업 세팅을 해야해. 진행해줘")
- 이 브랜치 안의 파일 변경과 로컬 커밋 — 받음 ("로컬 커밋을 승인하며")
- 반영 대상 브랜치를 `main`으로 확정 — 받음 ("반영 대상은 main이 맞다고 지금
  말해줄게")
- **설계와 실제 코드 수정을 포함한 009 진행 — 받음** ("작업 이어서 진행해줘.
  별도로 묻지말되"). 단계마다 진행 허락을 다시 묻지 않습니다
- push — **받지 않음** ("푸시는 진행하지 말아줘")
- `main` 반영 — **받지 않음**
- 대작업 종료와 아카이브 — **받지 않음**
- 작업 브랜치 삭제 — **받지 않음**

처음에는 세팅만 요청받아 구현 착수를 받지 않은 것으로 적어 두었는데, 그 뒤
사용자가 이어서 진행하라고 지시해 범위가 넓어졌습니다. 하지 말라고 한 넷은
그대로입니다.

## 현재 단계

**1~10단계 구현과 로컬 검증을 마쳤고 검토 대기 중입니다.** 009는 활성 상태로
유지합니다. main 반영·push·대작업 종료·아카이브·릴리즈·브랜치 삭제는 하지 않았습니다.
이번 사용자 지시는 이 로컬 브랜치의 수정과 로컬 커밋을 허용하고, push와 대작업
종료를 금지했습니다. 단계별 편집 허락을 다시 받지 않습니다.

## 직전 완료

2026-09-12 사용자 요청으로 직접 삭제의 사후 정리를 추가했습니다.

- AGENTS의 2026.md 표시 이름은 감사 제안, reviewed.md는 현재 검토로 맞췄습니다.
  도구가 새로 만드는 색인에도 같은 이름을 사용합니다.
- delete-fix는 ID 또는 경로로 범위를 고르고 누락된 발급 기록을 삭제 상태로
  바꿉니다. 이유는 사후 삭제 정리임을 표시해 남깁니다. 기본은 미리보기입니다.
- 들어오는 관계는 목록을 보여주고 중단하며 --drop-links로 명시한 경우에만
  독립된 명시 관계 줄을 제거합니다. 일반 링크·본문과 섞인 관계는 직접 정리합니다.
- 색인에서 빠진 외부 이동, 남아 있는 문서 파일, 손상 앵커와 손상·중복 대장은
  삭제로 오인하지 않도록 막습니다. 탐색 제외 위치로 옮겼는지는 사용자가 확인합니다.
- Git 없는 파일·문단 사후 정리, 범위 제한, CLI 미리보기·적용, 오류 주입과
  recover 회귀 시험을 추가했습니다. recover는 사후 정리 직전 대장·참조만 되돌리고
  이미 지운 본문은 만들지 않습니다.
- 설계·공통 결정·GRAPH·시험 보고서를 맞췄습니다. 저장소의 실제 아카이브를
  삭제하지 않았으며 살아 있는 폴더의 묶음 삭제 기능도 추가하지 않았습니다.

## 다음 행동

사용자 검토를 기다립니다. 구현의 남은 단계는 없습니다. 이후 결함이 발견되면
이 브랜치에서 고칩니다. main 반영이나 종료는 이번 실행 범위가 아닙니다.

않았습니다. 상세 검증과 제한은 docs/trials/README.md에 있습니다. 이번 변경의 원격 CI와
독립 에이전트 행동 시험, 사용자 설정에 설치한 훅 실행은 수행하지 않았습니다.
Stop 어댑터는 로컬 stdin·출력 JSON으로만 확인했습니다.

## 막힌 점과 열린 질문

- 구현을 막는 결정은 없습니다. GitHub 저장소 주소는 cairn 그대로이며, 원격 이름
  변경과 npm 등록은 하지 않았습니다. 주소를 바꿀 때 설치 안내와 package.json도
  함께 바꿔야 합니다.
- 외부 사용이 확인되지 않았다는 것을 사용자가 없다는 뜻으로 보지 않습니다.
  공통 decisions의 전제를 ideas와 009가 참조합니다. 007 원문은 참고 근거입니다.
- 정규화는 시험한 서식·구조 변화의 규칙이며 자연어 의미의 동치 판정이 아닙니다.
  새로운 Markdown 표현에서 문제가 드러나면 짝 입력으로 시험을 추가해야 합니다.
- 다른 에이전트가 ids 시험의 일회성 실패를 보고했으나 최초 상세 출력은 없었습니다.
  이전 실패와 같은 원인인지 확인하지 못했습니다. 이번 시험 통과를 원인 해결로
  확대하지 않으며, 관찰과 보고의 출처를 decisions.md에 구분했습니다.
