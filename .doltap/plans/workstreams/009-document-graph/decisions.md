## 링크 해시는 파일명이 아니라 대상의 정체를 남긴다

마지막 파일명만 남기면 폴더 이동에는 조용하지만, 서로 다른 폴더의 같은 이름 파일을
구분하지 못합니다. 관리 대상은 경로와 분리된 문서·범위 ID가 있으므로 그 ID를
남깁니다. 관리 대상이 아닌 파일은 안정적인 식별자가 없어서 이동과 대상 변경을
동시에 구분할 수 없습니다. 이 경우에는 저장소 루트 기준 전체 경로를 남겨, 이동도
재검토하되 다른 파일로 바뀐 것을 놓치지 않는 쪽을 택합니다.

## 복구 자료는 그래프와 Git에서 분리한다

여러 파일은 한 번에 원자적으로 바꿀 수 없으므로 백업과 manifest가 필요합니다.
이를 운영 문서와 같은 확장자로 두면 백업 안의 ID가 원본과 중복됩니다. 그래서
`<운영 폴더>/recovery/` 아래에 `.bak`과 JSON으로 두고, 그래프 탐색에서 제외하며
그 폴더의 `.gitignore`로 Git에도 들어가지 않게 합니다.

파일별 완료 표시는 쓰지 않습니다. 파일 교체와 완료 표시 사이에서 죽으면 바뀐
파일이 복구 목록에서 빠지기 때문입니다. 쓰기 전에 모든 원본·새 해시와 경로를
manifest에 확정하고, 복구할 때 예정 파일 전체의 현재 해시를 대조합니다.

## GitHub는 조각과 앵커의 어긋남을 메워 준다

GitHub는 앵커 이름에 `user-content-`를 붙이면서 링크 조각은 그대로 둡니다. 둘이
어긋나므로 그대로면 링크가 목적지를 못 찾습니다. 메워 주는 것을 근거 둘로
확인했습니다.

하나는 GitHub가 저장소 화면에 싣는 `behaviors-*.js`입니다. 조각을 읽어
`user-content-`가 없으면 붙인 뒤 그 요소를 찾는 코드가 들어 있고, 스크립트를
실제로 내려받아 확인했습니다.

다른 하나는 다른 세션이 실제 브라우저에서 공개 README의 목차 링크를 눌러 대상
절로 이동하는 것을 본 보고입니다. **이 관찰은 이 세션에서 재현하지 못했습니다** —
여기 쓴 브라우저는 앵커와 조각이 일치하는 대조용 파일에서도 스크롤하지 않아,
조각 이동 자체를 판정할 수 없는 환경입니다. 그래서 관찰은 관찰로, 코드 확인은
코드 확인으로 나눠 적습니다.

결론은 링크를 `#doltap-...`으로 쓰는 것입니다. `#user-content-...`로 쓰면 GitHub
밖에서 목적지를 잃습니다.

## `CLAUDE.md`에는 `mirror-of`가 아니라 `imports`를 쓴다

`design.md` 첫 초안은 `CLAUDE.md`와 `AGENTS.md`를 `mirror-of`로 이었는데, 같은
문서가 `mirror-of`를 「양쪽 `contentHash`가 같아야 한다」로 정의합니다.
`CLAUDE.md`는 `@AGENTS.md` 한 줄이므로 **언제나 불일치로 잡힙니다.** 검사기가
고칠 수 없는 오류를 영원히 내는 셈입니다.

두 파일은 같은 글이어야 하는 관계가 아닙니다. 한쪽이 다른 쪽을 읽어 들이는
관계입니다. 그래서 `imports`를 새로 두고 내용 비교를 하지 않습니다. 관계 유형이
13개에서 14개가 됐고, 설계 기록의 관계 표와 `CLAUDE.md` 특수 연결 설명도 함께
갱신했습니다.

## 검사기가 무엇을 놓치는지는 현재 문서로 알 수 없다

3단계를 마쳤다고 보고하면서 「`--schema next` 의 문제 43개가 전부 같은 종류이고
다른 오류가 없으니 오탐이 없다」고 적었습니다. 앞부분은 맞지만 뒷부분이
틀렸습니다. **문제의 종류와 개수만으로는 오탐과 미탐 어느 쪽도 알 수 없습니다.**
각 문제가 설계상 실제 위반인지 대조해야 오탐을 판단할 수 있고, 잡아야 할 입력을
따로 만들어야 미탐을 판단할 수 있습니다.

실제로 여섯 가지를 놓치고 있었습니다. 외부 URL 조각을 로컬 관계로 인정한 것,
앵커에 `name` 하나만 있어도 받은 것, `b` 안의 `b` 와 같은 관계 중복을 놓친 것,
외부 문서 등록과 `CLAUDE.md` 연결 노드가 아예 구현되지 않은 것, 숨김 폴더 제외가
이름 몇 개만 본 것입니다. 어느 것도 이 저장소의 현재 문서로는 드러나지
않았습니다 — 아직 앵커가 하나도 없기 때문입니다.

그래서 시험의 짝은 **설계 문서에서 뽑습니다.** `design.md`가 정한 규칙마다
어기는 입력을 일부러 만들고, 그것이 잡히는지 봅니다. 현재 문서를 돌려 보고
조용하면 통과로 보지 않습니다.

시험이 실제 경로를 타는지도 따로 봅니다. 외부 문서 등록은 시험에서 문서를 배열에
직접 넣어 `collectDocuments` 를 건너뛰고 있었습니다. 통과하는 시험이 아무것도
검사하지 않고 있을 수 있습니다.

외부 문서 등록은 저장소 경계와 탐색 제외 규칙도 같은 경로에서 적용합니다. 관계가
있다는 이유로 `../`를 통해 저장소 밖을 읽거나, 숨김·복구·의존성 폴더와 심볼릭
링크를 우회하거나, 마크다운이 아닌 파일을 그래프에 넣지 않습니다. 기본 탐색과
관계 등록이 서로 다른 관리 범위를 만들면 안 됩니다.

## 이름이 정해진 뒤에도 5단계까지는 현재 경로를 가리킨다

이름을 정했다고 문서가 `.doltap/`을 가리키기 시작하면, 아직 존재하지 않는
폴더를 가리키는 글이 됩니다. 실제 이관은 `plan.md` 5단계이고, 그전까지 이
저장소의 운영 폴더는 `.agents/`였습니다.

그래서 5단계 이전 문서에서는 `.doltap/`과 `doltap` 명령을 **앞으로 그렇게 된다는 설명**으로만
썼습니다. 지금 무엇을 읽고 실행해야 하는지 알려 주는 자리에는 현재 경로와 현재
명령을 그대로 둡니다.

불변 ID도 같습니다. 접두사는 `doltap`으로 정해졌지만 발급은 4단계와 6단계에서
시작합니다. 파서와 발급 기록이 없는 상태에서 먼저 박아 두면 중복 검사와 재사용
방지를 거치지 않은 ID가 남습니다.

덧붙여 현재 검사기는 활성 문서에 남은 임시 골격 참조를 확인 항목으로 올립니다.
기본 이름 뒤에 경로가 이어진 것만 세므로, 이름을 말로 부르는 문장은 걸리지
않지만 폴더 구조를 예시로 적으면 걸립니다.

## ID 발급은 수명 주기 상태를 암묵적으로 바꾸지 않는다

대상에 이미 ID가 있으면 발급기는 같은 ID를 돌려주고 마지막 경로만 갱신합니다.
이 확인만으로 `아카이브`를 `활성`으로 바꾸지 않습니다. 단순 재실행이 상태를
바꾸면 레거시 아카이브에 ID를 소급하는 과정에서 과거 문서가 활성 문서로 등록될
수 있기 때문입니다.

새 아카이브 문서는 처음부터 `아카이브` 상태로 발급 기록에 넣습니다. 기존 범위를
복원할 때는 상태 변경을 별도 작업으로 명시합니다. 같은 ID가 레지스트리에 두 줄
있으면 첫 행을 원본으로 추측하지 않고 변경을 멈춥니다. 뒤쪽 행이 삭제 표식이면
첫 활성 행만 보고 삭제 ID를 되살릴 수 있기 때문입니다.

잠금 파일은 배타적 생성만 성공했다고 완성된 것이 아닙니다. PID와 시각을 모두 쓴
뒤에야 유효합니다. 내용 기록이나 파일 닫기가 실패하면 파일 핸들과 불완전한 잠금을
정리하고 원래 실패를 알립니다. 빈 잠금은 동시 실행 중인 다른 프로세스가 막 만든
것일 수 있어 자동으로 빼앗지 않으므로, 만든 쪽이 실패 경로에서 정리해야 합니다.

## 계획 커밋을 기준 브랜치가 아니라 작업 브랜치에 둔다

`workstreams.md`의 기본 절차는 계획을 기준 브랜치에 커밋한 뒤 거기서 작업
브랜치를 가르라고 합니다. 다른 세션이 기준 브랜치만 읽어도 무엇이 진행 중인지
볼 수 있게 하려는 것입니다.

여기서는 그렇게 하지 않습니다. 사용자가 로컬 브랜치를 만들어 그 안에서
진행하라고 했습니다. 007과 008도 같은 이유로 계획 커밋을 작업 브랜치에 뒀고,
그 기록이 각 `status.md`에 남아 있습니다.

무엇을 잃는지 적어 둡니다. `main`의 `current.md`는 진행 중인 대작업이 없다고
말합니다. 이 브랜치를 모르는 세션은 이 대작업을 찾지 못합니다. 이어받으려면
브랜치 이름을 알아야 합니다.

## 6~10단계에서 구체화한 명령과 검증

사용자가 이번 대화에서 이 로컬 브랜치의 편집과 로컬 커밋을 허용했습니다.
push와 대작업 종료는 금지했고, main 반영과 브랜치 삭제도 하지 않습니다.

`migrate`, `delete`, `archive-check`, `suggest`와 `review --node`를 추가했습니다.
모든 쓰기는 같은 백업·manifest·잠금을 사용하며 미리보기 뒤 `--apply`로 실행합니다.
CLI가 워크스트림 종료를 자동으로 실행하지 않도록 아카이브는 사전 검사만 제공합니다.
삭제 이유는 별도 임의 문단이 다음 발급 때 사라지지 않게 레지스트리 여섯째 열로 둡니다.

맥락 예산은 본문 문자 수로 명확히 정했습니다. 초안의 루트 본문을 무조건 끝까지
출력한다는 문장은 예산 제한과 충돌하므로 루트도 잘라 생략을 표시합니다. ID·경로·
관계 메타데이터는 예산 밖임을 출력과 사용법에 명시합니다. 내용 누락을 숨기지 않습니다.

5단계 기계 치환으로 채택 이름이 동시에 기각 후보가 되고 남의 프로젝트 폴더까지
바뀐 곳을 원래 역사와 대조해 복구했습니다. 완료 기준 자체를 줄이지 않았습니다.

Git·에이전트 훅은 예시와 선택적 Stop 어댑터만 제공합니다. 공식 문서의 입출력 형식과
로컬 어댑터 시험을 실제 사용자 설정에 설치한 실행 검증으로 확대하지 않습니다.

## 실제 문서 검증에서 보완한 판정

아카이브 사전 검사에서 design.md의 문법 설명을 실제 전제로 세는 오탐을 발견했습니다.
살아 있는 항목 표식은 줄 첫머리(선택적 목록 표식 뒤)의 단일 백틱으로 구분하고,
코드 예시·표·인용 설명을 제외합니다. 자식 범위는 자기 선언만 판정하게 실제 본문
시작 줄도 기록합니다. 종료 기준 변경이 아니라 확정 문법의 오탐 수정입니다.

기존 절 안의 하위 절에 ID를 요청하면 상위 ID를 되돌리던 경우도 분리했습니다.
init은 복구 디렉터리·잠금을 복사하지 않고, 직접 발급 API로 레지스트리를 갱신해도
문서 ID를 유지합니다. 모두 회귀 시험에 포함했습니다.

README 완료 조건의 「가칭 doltap이 남지 않음」은 이름 치환이 만든 모순이므로
「옛 이름 cairn이 남지 않음」으로 바로잡았습니다. 채택한 이름이나 완료 범위를
바꾼 것이 아닙니다. 원본 설계의 대응 문구도 같은 뜻으로 고쳤습니다.

추가 경계 입력도 확인했습니다. 공백·#이 든 경로는 URI로 인코딩하고 읽을 때
복원합니다. 일반 ID 링크도 잘못된 파일을 가리키면 오류로 냅니다. 중첩 목록의
들여쓰기는 부모·자식 의미가 있으므로 내용 정규화에서 보존합니다.

5단계 이전에 전체 시험 한 건이 한 번 실패했지만 원인을 확정하지 못한 기록이
있습니다. 당시 단독·동시 반복 실행으로 재현하지 못했고, Windows rename의
재시도 여유를 200ms에서 2초로 넓혔습니다. 이번 최종 통과를 그 원인이 해결됐다는
근거로 사용하지 않습니다.

## 후속 검토와 현재 원본의 위치

2026-09-12 사용자 요청으로 첫 검토의 즉시 만료, 감사의 검토 불가 후보·필터 누락과
상대 경로 정규화를 수정했습니다. 손상된 기존 검토 기록을 덮어쓰던 경우도 차단했습니다.
회귀 시험은 test/review.test.mjs에 있고 보고서는 docs/trials/automated/review.md에 있습니다.

프로젝트 공통 결정과 살아 있는 전제는 plans/decisions.md로 승격했습니다.
009의 외부 사용 전제 block ID는 그대로 옮겼습니다. ideas와 009는 활성 원본을
참조하고, 007 원문은 참고 근거로 남습니다. 아카이브 의존은 필수가 아닙니다.

기존 50개 관계는 indexes 44개, imports 1개, references 1개, assumes 3개,
derived-from 1개였습니다. 상태 검토 관계는 4개였으므로 의미 관계가 2개라는 수는
계산 기준이 필요합니다. 다만 운영 문서의 의미 연결이 제한적이었다는 평가는 맞습니다.
개수를 늘리려고 관계를 추가하지 않고 실제 원본·적용 범위가 분명한 연결을 기록합니다.

로컬 폴더 이름은 코드·Git 이력과 분리되어 있습니다. 현재 저장된 작업 경로가
checkout 폴더를 가리키므로 작업 중 그 폴더를 이동하지 않습니다. 독립 복사본의
이름 변경으로 CLI와 문서 링크를 확인하고, 실제 변경 때는 편집기·터미널을 닫고
형제 doltap 경로로 옮긴 뒤 새 경로로 프로젝트를 엽니다. 원격 URL은 별도로 유지합니다.

## 추가 검토와 project 문서 이동

2026-09-12 사용자 요청으로 project.md를 plans/project.md로 옮기고 운영 원본과
배포 template, 검사기, 이관 명령, 사용 안내와 시험을 함께 맞췄습니다. 기존 ID는
유지하며 두 위치의 파일이 충돌하면 자동 이관을 중단합니다.

넘겨받은 --root 안내, 훅 신뢰 절차, 이월 시험과 보고서 설명 수정을 대조했습니다.
보고서 검사에서 불필요한 폴더 생성과 여분의 잘못된 행을 놓치는 문제를 추가로
수정했습니다. 임시 복사본에서 두 입력을 확인했습니다.

다른 에이전트는 ids 시험이 한 번 실패한 뒤 반복 실행에서 재현되지 않았다고
보고했습니다. 그 최초 실패의 상세 출력은 없으므로 이전 일회성 실패와 같은 원인으로
묶지 않습니다. 현재 반복 통과만으로 원인 해결을 주장하지 않습니다. 보고 도구는
실패 시 TAP·프로세스 오류·종료 신호를 출력합니다.

누적 검토는 원본 설계의 Git 비의존 판단 이력 요구와 자기 참조 방지에서 나왔습니다.
현재 해시와 맞는 과거 검토의 재사용도 원본 설계에 명시돼 있습니다. 백업의 수동
폐기는 결과 확인 전 복구 가능성을 남기기 위한 선택입니다. 다만 이력 보존이 과거
검토 재사용을 필수로 만드는 것은 아니고, 전체 파일 백업의 무제한 누적도 필수는
아닙니다. 사용자 요청은 개선안 검토이므로 현재 판정과 보관 정책은 유지하고
제안은 plans/ideas.md에 둡니다.
