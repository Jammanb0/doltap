# 프로젝트 공통 결정과 전제

여러 작업에 계속 적용되는 결정과 그 이유의 현재 원본입니다. 규칙의 적용 문구는
AGENTS.md와 rules에, 프로젝트 설명은 project.md에, 미착수 후보는 ideas.md에 둡니다.
워크스트림 decisions.md에는 그 작업의 선택 과정과 당시 근거를 보존합니다.

## 제품 이름

공개 이름·패키지·CLI는 doltap, 운영 폴더는 .doltap, 임시 적용 폴더는
.doltap-bootstrap입니다. GitHub 저장소 주소와 로컬 checkout 이름은 별도입니다.
이름 충돌은 키워드 검색이 아니라 이름 일치 검색으로 봅니다. 키워드 검색은 별 수로
정렬해서 같은 이름의 작은 저장소를 덮습니다.

## 검토와 자동화

문서와 명시 관계가 원본이고 지도는 파생물입니다. CLI는 AI API를 호출하지 않습니다.
노드 내용 검토와 관계 영향 검토를 구분하고, 관계별 판단을 이유·주체와 함께 남깁니다.
검토 기록은 사용자 승인이나 내용의 참을 증명하지 않습니다. 수동 검사가 기본이며
Git·에이전트 훅은 사용자가 필요할 때 연결합니다.

## 현재 정보와 과거 근거

지금 따라야 하는 내용은 활성 문서만 읽어도 알 수 있어야 합니다. 작업에서 나온
공통 규칙·전제는 종료를 기다리지 않고 담당 활성 원본에 반영합니다. 옮긴 항목은
같은 ID를 유지하고 이전 위치를 현재 참조로 바꿉니다. 과거 원문을 보존해야 한다면
현재 원본에는 별도 ID를 발급하고 출처 관계만 남깁니다. 같은 ID를 복제하지 않습니다.
아카이브는 그때 왜 결정했는지 확인할 때 읽습니다. 현재 규칙이 자동으로 되지는 않습니다.
특정 과거 결과 자체에 의존해야 할 때에만 그 관계를 명시합니다.

## 프로젝트 설명의 위치

프로젝트 방향과 작업을 한곳에서 찾도록 project.md를 plans/ 안에 둡니다.
기존 ID는 유지합니다. 계획·공통 결정·아이디어·이력을 이미 이 폴더에서 관리하므로
프로젝트 목적과 범위도 함께 찾도록 하는 사용자 결정입니다. 각 문서의 역할은 유지합니다.

## 지원하는 마크다운 렌더러

앵커와 링크 조각이 실제로 동작해야 하는 범위는 GitHub 저장소 화면과 VS Code 기본
마크다운 미리보기 둘입니다. 모든 렌더러의 HTML 위생 처리 차이를 보장하지 않습니다.
이 프로젝트의 문서를 실제로 읽는 웹·로컬 화면이 그 둘이라서 고른 범위입니다.
다른 렌더러에서 조각이 동작하지 않는다면 그 렌더러를 지원 범위에 넣을지부터 정합니다.

## 설계 원본과 아카이브의 경계

큰 방향은 `docs/document-graph-design.md`, 정확한 현재 사양은
`docs/document-graph-spec.md`, 명령 사용법은 `guide/reference.md`에서 관리합니다.
세 문서는 활성 문서이며 워크스트림을 아카이브해도 옮기지 않습니다.
워크스트림의 `design.md`는 그 작업 동안의 상세 설계이므로 폴더와 함께 아카이브되고,
그 뒤에도 유효한 사양은 아카이브 전에 담당 활성 문서로 올립니다. 활성 사양이
아카이브 폴더에만 남는 상태를 허용하지 않습니다.

## 최신 검토 기준

노드·관계 검토는 reviews/reviewed.md에서 대상별 최신 한 건만 덮어씁니다.
현재 내용과 마지막 검토를 비교하며 일치하는 과거 검토를 재사용하지 않습니다.
Doorstop처럼 마지막으로 확인한 상태를 기준으로 삼고 반복 검토의 누적을 없애려는
사용자의 A안 선택입니다. 과거 검토 이력 파일은 만들지 않습니다. Git 없이도 동작하지만
과거 판단 보존은 보장하지 않으며 Git에도 커밋한 버전만 남습니다.

감사 제안의 반영·기각·보류는 연도별 파일에 계속 남깁니다. 이는 감사 시 호스트가
이전 판단을 참고하는 자료입니다. CLI가 AI의 재제안 여부를 직접 제어하지는 않습니다.
복구 백업·미완료 실행 보호·수동 폐기 방식과 삭제된 대상 기록 정책은 유지합니다.

## 직접 삭제 후 정리

파일을 이미 지웠을 때 Git 복원을 강제하지 않습니다. delete-fix에서 범위를 지정해
누락 ID를 삭제 상태로 바꾸고 이유를 남깁니다. 들어오는 관계의 제거는 --drop-links로
따로 명시하며, 일반 문장이나 의미 판단까지 자동으로 정리하지 않습니다. 정상 삭제는
delete로 먼저 영향을 확인하고, delete-fix는 이미 사라진 범위만 처리합니다.
복구는 명령 실행 당시 남아 있던 대장과 참조에 한정됩니다.
